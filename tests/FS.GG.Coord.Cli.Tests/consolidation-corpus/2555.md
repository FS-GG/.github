`scripts/test` derives "which suites should this change run" by scraping the workflows' `run:` blocks.
Its ENTIRE scrape vocabulary is two regexes:

```python
RX_SHELL  = re.compile(r"(?:bash|sh)\s+(tests/[\w.@/-]+\.sh)")
RX_DOTNET = re.compile(r"dotnet\s+test\s+(tests/[\w.@/-]+\.fsproj)")
```

*Verification:* `scripts/test:101-102` at `7ca9474a`.

## Observed

A suite whose runner is python or node is **structurally invisible** to derivation. It can be genuinely
wired — named in a workflow's `run:` step, executed on every matching PR — and `scripts/test --list`
still reports its directory under `UNWIRED`, because `scrape()` matched nothing.

The live witness is already in the tree:

```
$ grep -n "tests/preset-repo-scope-coherence" .github/workflows/preset-repo-scope-coherence.yml
97:        run: bash tests/preset-repo-scope-coherence/run.sh
112:        run: node tests/preset-repo-scope-coherence/drive-package-rules.mjs
```

Line 112 is a wired suite this selector cannot see. The directory escapes the `UNWIRED` list only
because line 97 gives it a sibling the selector CAN see. Remove that sibling and a fully-wired,
CI-executed suite would be reported as never run.

*Verification:* both line numbers read from `.github/workflows/preset-repo-scope-coherence.yml` at
`7ca9474a`; `python3 scripts/test --list --all` at the same commit does not list
`tests/preset-repo-scope-coherence/` under `UNWIRED`.

## Root cause

The scrape vocabulary is a closed two-entry list, and — unlike the `paths:` derivation this script is
built around — it is a **copy of a convention rather than a derivation of one**. `scripts/test:34-39`
states the deliberate boundary ("WHICH suites to run comes from the workflows; HOW to run one is
canonical per kind"), and that boundary is right; the defect is that the set of kinds was frozen at two
while the repo grew a third (`node`) and a fourth (`python3`) in `tests/`.

## Why it matters now

`.github#2537` turned the `UNWIRED` report into a refusal (`scripts/test --assert-wired`). Under that
gate, invisibility is no longer cosmetic: `tests/coord-report/run.py` **cannot be discharged by wiring
it**, because wiring it changes nothing the selector can observe. Its only available answer becomes a
`DELIBERATELY_UNWIRED` exemption that says "deliberate" about something that is not deliberate — a
false entry in the one list whose value is that its entries are true. `.github#2537` recorded the fact
in that entry's reason rather than writing the false one, and this row is where it gets fixed.

## Acceptance criteria

1. `scripts/test` sees a python suite (`python3 tests/<dir>/<file>.py`) and a node suite

2. `tests/preset-repo-scope-coherence/drive-package-rules.mjs` is derived as a suite — demonstrated,
   not asserted: deleting line 97's `bash` step from `preset-repo-scope-coherence.yml` must leave the
   directory OUT of the `UNWIRED` list, where today it would drop into it.
3. Gate-inversion: `tests/test-selector/run.sh` gains a leg that reds when the new vocabulary is

4. `tests/coord-report`'s `DELIBERATELY_UNWIRED` entry in `scripts/test` is re-examined once this
   lands — it is half-blocked on this row and says so.
