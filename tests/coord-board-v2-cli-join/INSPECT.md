# Read-only CLI contract

```sh
fsgg-coord-engine board-v2 inspect --binding-file reviewed-binding.json --report-file new-inspection.json
```

The binding must identify the loaded adapter, protected population blob and exact
selected native cohort. Historical/product output is `fsgg.coord.board-v2-inspection/1`;
organization-v4 output is inspection/2, described below. Both record
current native issues, complete dependency reads, owning plans and human Status,
Roadmap and Track separately from Observation and source currentness.

An unavailable population produces `selected: null`, a population gap and no
candidates (exit 3). This is unknown coverage. Missing planning values remain null;
Unknown Observation remains Unknown. Native closure or human Done never supplies
outcome acceptance. Programme-v4 reads native PR/file facts directly and joins explicitly
attributed current integrator observations for action/runtime facts. Missing suppliers
remain Unknown. Candidates do not dispatch or authorize work.

Version-4 binding/report files use an existing restrictive private parent directory
without symlink components. New reports are exclusive mode0600 and use the existing
Linux x64 directory-entry barrier. Product-v3 paths and report behavior remain separate.

Inspection performs queries and bounded dependency/issue-author-permission GETs only. It never sends or
retries mutations, changes board fields, creates projection timestamps or takes the
refresh writer lock. Optional `--previous-report-file` reads a refresh/v2 report
only to retain historical LastVerified; history never proves currentness.


## Programme successor source window

Organization `bindingVersion: 4` requires exact Project 3 identity, `schemaVersion: 2`
and six Status options including In review. Product binding version 3 retains its
separate five-status contract. Historical organization v2 controls grant no successor
selection or fallback. Programme refresh uses the existing Observation-only writer after exact successor
schema/native/source checks. An installed old Project 3 schema still refuses before
mutation; source support does not authorize schema migration or live board changes.

The fixed protected manifest path holds only the closed two-field public
`fsgg.coordination-board-v2-enrollment/v3` document: `schema` and
`commitmentSha256`. Programme identity and Roadmap values remain in the private
binding's closed `programmeEnrollment` pair (`nonceHex`, `payloadBase64`). The nonce
contains 32 random bytes; canonical padded Base64 carries the exact UTF-8 private
payload, without a BOM. Its closed payload/v1 binds `target`, constructor `binding`
and the entire selected `items` cohort (issue, nodeId, roadmap). No issue revision,
open state or empty-dependency snapshot belongs to enrollment.

The commitment hashes the ASCII domain `fsgg.coordination-board-v2-enrollment/v3`,
one NUL byte, the decoded nonce, an unsigned eight-byte big-endian payload length
and the original payload bytes. It never hashes reserialized JSON. Runtime verifies
the exact protected public blob and private digest before selected issue/plan reads,
then rechecks public currentness after inspection and before refresh writes or a
Verified no-op. Missing, changed or mismatched enrollment withholds population selection.
The report joins public source provenance and the matched commitment; it excludes
private payload and nonce. Selected plan paths remain stable while their current
protected-main blobs are observed.

Binding acquisition is bounded to 256 KiB on the same opened handle before allocation;
the private payload is bounded to 128 KiB and JSON depth to 16. Duplicate, unknown or
missing fields, invalid UTF-8, noncanonical Base64, wrong scope/provenance and incomplete
cohorts refuse. Product-v3 input remains unchanged and rejects `programmeEnrollment`;
there is no raw-public programme fallback.

The maintained offline `BoardV2Import prepare-programme` command accepts a reviewed
binding template and complete private payload, validates before generating one random
nonce, and retains exclusive restrictive private/public output files with flush and
readback checks. Partial outputs remain original evidence; collisions do not overwrite,
reseed or retry. Its outputs are preparation only. A reviewed protected public commit
and qualified installed executable are still required for admission. Never put private
inputs, nonce or binding in a public checkout, fixture, artifact or PR.

Inspection/v2 adds complete membership reconciliation and actual repository-wide open
PR inventories, including non-enrolled work, native closing-issue associations, head,
files, reviews and checks. Connections drain within existing bounds; denied/partial
reads and final issue/dependency/plan/planning/membership/head changes remain unknown.
Unexpected cards stay visible and unenrolled. No human planning field is written.
When native PR collection was never attempted (including failed global admission or
product-only inspection), the typed API uses MinValue solely as an absent-observation
sentinel; it never passes freshness, even at a MinValue evaluation time. The programme
wire emits `nativeIntegrator.observedAt: null`. A real collection attempt retains its
conservative start time and its read gaps; final barrier failures do not renew it.

The production organization-v4 `inspect` command accepts one optional
`--integrator-stdin` document (`fsgg.coord.board-v2-integrator-observations/1`).
The existing parent integrator supplies it for one invocation. Its required
`enrollmentCommitmentSha256` must match the private binding commitment before native
IO and the authenticated public source evidence before selection. Inspection/2 reports
the matched `enrollmentCommitmentSha256` (null on unmatched population); protected
inputs use `programme-enrollment/v3-commitment`. Neither contains nonce or raw payload.
The other input joins retain stable slice and
attempt IDs, explicit operation/order, accountable outcome owner and implementation
owner, original supplier/time/expiry/evidence, exact binding/enrollment blob and
native issue ID/update/body/source-plan revision joins. Source editing consumes one
implementation slot; review and qualification require an existing native PR/head
and consume only their matching review or hosted-CI slot. Counts explicitly mean
remaining after active work. Read-only existing-PR observation consumes no new slot.
Activation remains Unknown under its operation-specific owner route.

The closed parser refuses duplicate/unknown/missing keys, trailing documents,
out-of-scope issue/repository identities, negative counts and excessive byte/depth/
array/text bounds before native reads. Stdin is consumed once and never cached or
saved. Product-v3 and refresh reject the flag without consuming stdin. No flag means
stdin is untouched. `runWithTransportAndInput` exercises this exact caller path with
an injected reader; production uses `Console.In` without process-global test changes.

Every reported runtime/action/prerequisite/intake/reservation observation is labeled
`integrator-reported`, not authenticated native evidence. File permissions, supplier
names, fresh timestamps and the exact input digest do not authenticate its author.
The accountable parent verifies genuine supplier observations through its existing
work-programme authority; missing suppliers remain Unknown. Native Current deliverable
links are discovery hints, directly joined to native PR identity/state/head and complete
open inventories, including non-enrolled work. The maintained issue model requires one complete,
unambiguous six-field record, expressed as six headings or six inline fields; duplicate, missing,
mixed or unknown field structure refuses. Preserve the bounded Current deliverable declaration:
exact trimmed `None` declares absence; nonempty prose and non-PR references remain declared work.
PR-shaped references retain strict canonical validation and native joins. Non-PR links are not
fetched, and Next action or arbitrary history never supplies a current PR association.

Each non-`None` declaration requires exactly one proposed-action prerequisite whose reference is
`current-deliverable`, with the existing fresh issue/body, slice, attempt, owner and evidence joins.
True means scoped reconciliation of current work against that action, not acceptance or release of
original holds. False blocks; missing, duplicate, stale or mismatched evidence withholds the affected
selection. Native inventories and reservations remain independent. Historical PRs cannot become
current through this observation; review, qualification and existing-work observation still require
their actual native PR/head. Independent source work may proceed when later acceptance is pending.

Native repository-policy/issue-author allowance reuses `BoardIntake.Gate` without disk
cache reads or writes, remains separate from parent operation authority, and is bound
to the exact current native issue ID/revision. All reads share the existing request/time
ceiling; cache/invocation observation timestamps cannot be renewed by later joins.

Selection folds the explicit supplied order into per-slice Ready/deferred results,
consuming only selected operations' capacity and conflicts. Unselected alternatives
are not reservations. Original holds retain their custody references; stale observations
never release them, and self exemption requires the exact slice/attempt/operation/PR/head.
Relevant repository read gaps withhold affected slices; global enrollment/schema/
membership gaps withhold all. Unknown native paths cannot prove disjointness.

This is source composition, not installed/real-use acceptance. Reports grant no dispatch,
capacity allocation, publication, effect retry or native acceptance authority. The existing
integrator must recheck determining native/runtime facts beside actual owner execution
and recompute remaining proposals after dispatch changes active state. Collaboration slots
are not implementation/review/CI observations. No new scheduler, ledger, persistent
per-edit manifest or retired protected-intake-preflight is introduced. Health/Observation

Version-4 Observation refresh is source-complete through the existing one-shot writer:
current enrollment/source are rechecked even on a Verified no-op, every intended write
is independently read back, and lost/uncertain responses never dispatch a retry. It
writes only Observation and does not consume the selection overlay or runtime capacity.
Concurrent human Status/Track/Roadmap values survive. Original .103 uncertainty remains held;

Focused source builds and inert caller tests are separately bounded; required hosted CI remains. Neither is native installed or browser acceptance.


## Bounded migration source contract

The accepted 0.104 package and installed-byte qualification remain tied to their original candidate.
The visibility correction described here is later source; source builds and inert caller tests do
not update that installation or grant another apply. Original partial/Unknown invocations retain
readback-only custody. A genuine qualified successor and fresh selected preparation precede any
remaining mutation; supported human UI edits are legitimate new facts for that preparation.

The packaged `board-v2` route also prepares the selected .10 migration. This source is not an
installed candidate or a live-operation grant. The accountable owner separately selects the exact
operation after installed qualification; native principal/capability establishes permission only.
The original .103/.104 operations and all unresolved holds remain separate.

```text
board-v2 migration-prepare --scope-file PRIVATE_SCOPE --report-file ORIGINAL_NEW_PRIVATE_PATH
board-v2 migration-apply --prepared-file ORIGINAL_PRIVATE_PATH --prepared-sha256 SELECTED_SHA256 --accountable-owner OWNER --selection-reference EVIDENCE_REFERENCE --planning-window-until RFC3339
board-v2 migration-readback --prepared-file ORIGINAL_PRIVATE_PATH
```

Scope input is closed and bounded to 256 KiB; it is planning data, never an approval flag. Preparation
uses two complete stable native snapshots, records the original report path, and leaves new native
option/view IDs unresolved. It can report unavailable update capability without requiring write access
for the read-only report. Apply binds selected prepared bytes, actual executing source/CLI/adapter
identities, native principal/capability, exact fresh scope and a finite planning window. Copying
unchanged prepared bytes to a different path refuses before native reads or a new reservation.

The original path owns its exclusive reservation and private invocation directory. Exact intent and
request bytes precede each one-shot send; file flush and production Linux x64 directory-entry barriers
must succeed. Unsupported barriers refuse; source review is not runtime filesystem qualification.
Expiry is checked after custody and at native acquisition. Reopening a retained invocation is
readback-only, including partial, malformed, lost or uncertain responses; no retry, overwrite,
rollback, alternate evidence path or caller-JSON grant is introduced.

All native reads/effects share 500 requests / 270 seconds. The fixed-origin sender bounds request bytes,
response acquisition and remaining time, with no redirect or automatic retry. Determining read and
mutation responses require clear envelopes; incomplete pages/errors retain gaps. Each effect refreshes
schema/views/memberships and independently reads back exact native identities. A clear correlated
created-view ID plus complete same-ID readback may resolve only its originally selected dependent
filter update within the same invocation. Existing human planning values, option/card identities,
unrelated views and orthogonal grouping/vertical/sort configuration remain preserved. API metadata
cannot verify UI columns/cards/order or replace actual installed Project 3 acceptance.

After a clear correlated successful response, an exact complete pre-effect snapshot may mean
pending native visibility. The same complete snapshot must establish both returned identity and the
exact selected transition before proceeding. The caller sends only once and may retain up to seven
complete readbacks with waits of 1, 1, 2, 4, 8 and 14 seconds (at most 30 seconds total). Only the existing project timestamp and the
existing target-item timestamp allowance for initialization are normalized; unrelated facts stay
strict. Conflicting/partial/error reads, invalid response identities and uncertain sends stop Unknown.
There is no resend or absence-as-NoSend inference.

A complete exact pre-effect witness may support only waiting without the second identity query.
Every candidate-confirmed witness still receives the existing final project/principal/capability
identity recheck on that same data before advancement. Partial pages never become Pending; standard
prepare, precondition and original-path readback collections keep their full identity barrier.

Observation acquisitions and waits consume the original 500-request/270-second envelope and selected
planning deadline. The transport exposes remaining time from that original stopwatch; it does not
start another budget. A wait that cannot fit refuses. Every additional witness stays in the same
exclusive invocation custody. Exhaustion remains incomplete/readback-only, including when a full
many-effect journey cannot fit. The inert 77-effect case with one stale read per effect uses 468
apply requests and 77 virtual seconds; the separate preparation uses four more requests. Its no-lag
sibling uses 391 apply requests. These counts exclude real HTTP and custody latency and do not prove
native fit. This source contract does not retroactively repair or reactivate an older installed
package or original partial invocation.

The closed scope now includes `initialPlanning`: explicit selected issue identities, exact Track
option ID/name, genuine Roadmap text and an optional selected Status option. Use an empty array when

Creation is one typed effect for the exact Work level SINGLE_SELECT field and fixed two option

Qualify the selected caller's actual Project 3 reads and the repository evidence needed by each

## Interpreting original native qualification results

The existing bounded command helper exposes `qualify_board_v2_result` in
[`scripts/update_fsgg_coord_cli.py`](../../scripts/update_fsgg_coord_cli.py). Its pure
[decoder](../../scripts/board_v2_native_results.py) reads original results; it does not
launch commands, write native state, grant effect authority or retry a failed operation.
The installer's fixed public-package command remains unchanged.

Pass the original command record, including raw stdout, terminal exit and both EOF
observations. `kind="inspection"` reads the exact `source_path` report file and requires
an explicit expected binding: `bindingVersion`, `schemaVersion`, `projectId` and the
complete `selectedIssues` map. Product binding3/inspection1, historical organization4/
inspection2 and organization5/inspection3 retain their separate shapes. `Observed`
means the result decoded; each report's Unknown evidence and advisory-only decisions
remain unchanged.

For `kind="migration-prepare"`, pass the original `--report-file` as `source_path`,
the exact `expected_scope` sent and its `expected_source_revision`. This read-only
qualification requires empty stdout and `changes: []`; the returned `value.snapshot`
contains every reported field, item, view and selected native issue. A conflicting or
nonempty preparation supplies no transition permission. The ordinary `ownerActions`
warnings remain retained. No migration apply, invocation marker or journal is needed
merely to qualify this fresh snapshot.

For `kind="migration-readback"`, pass `prepared_path` and one exact original
`source_path` under its `.invocation/readback-<32hex>.json` custody directory. The command
intentionally emits no JSON stdout. The decoder reads that file and the invocation's
original `prepared.json`, checks their schema/scope association and preserves byte-hash
references. An optional `expected_sha256` pins either selected output's original bytes.
These references identify bytes; they do not independently authenticate an installed
executable or recompute the native preparation/readback digest.

`decode_field_value` distinguishes the actual text and single-select unions.
`require_preimage` refuses changed facts; compare the complete initial and adjacent
`value.snapshot` values to retain native scalar identity/revision changes even when the
human value is unchanged. After an independently
admitted native transition, `verify_field_transition` compares the complete before/
after reported snapshots, permits only the selected scalar value and its enclosing
native timestamps to change, and checks all other reported values and identities.
Opaque system-field contents and hidden native fields remain unproved. These readers
provide no server-side compare-and-swap; the actual owner still needs a fresh adjacent
preimage, current options and a bounded cooperative planning window before sending.

A missing, partial, invalid, mismatched or lost command/result remains `Unknown` with
its available original references. Reconcile that original identity through read-only
observation; a decoder failure never licenses resend. Focused controls run through the
existing command helper in `tests/update-fsgg-coord-cli/test_update.py`, reached by the
existing installer self-test workflow, including its decoder-source path trigger.
