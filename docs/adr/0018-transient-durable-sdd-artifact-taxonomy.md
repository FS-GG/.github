# ADR-0018: Transient vs durable SDD artifact taxonomy — regenerable process output is gitignored by role, not committed per-feature

- **Status:** Proposed
- **Date:** 2026-07-04
- **Affects:** SDD (canonical taxonomy + `init` `.gitignore` seed), Rendering (exception-list collapse + tree cleanup), Governance (adopt fragment; keep the audit record), Templates (adopt fragment + cleanup), .github (this ADR)

## Context

Committed Markdown across the four FS-GG repos measures **~473k lines — larger than the
~309k lines of F# source** (measured 2026-07-04), and ~87% of it is Spec-Kit / SDD *process
output* rather than authored docs or code. A large slice is **regenerable per-run evidence**
that the repos already classify as transient, yet commit anyway. Tracked as the cross-repo
umbrella [FS.GG.SDD#110](https://github.com/FS-GG/FS.GG.SDD/issues/110).

The Rendering `.gitignore` is the clearest symptom. It ignores readiness evidence as
transient (`specs/*/readiness/` — "regenerated on every run, never committed") and then
carries **98 per-feature `!specs/<feature>/readiness/**` re-inclusion exceptions**. Net today:

- **2,053 committed readiness files (~35.4k lines)** under `specs/*/readiness/` — 955 `.md`,
  923 `.json`/`.log`/`.txt`/`.png`.
- A 150+ line `.gitignore` maintained by whack-a-mole: every new feature adds an exception.

The convention for *which SDD process artifacts are durable vs regenerable* is owned by the
SDD lifecycle, but the footprint lands in **all four** consuming repos. There is no
cross-repo surface that states the split, so four repos make four divergent local decisions.

Three facts shape the decision:

- **SDD already classifies this at machine precision.** `release-readiness.json` and its
  projection `docs/release/schema-reference.md` mark every `readiness/<id>/*` path a
  **generated view** (`owner: generatedProduct`, byte-stable, regenerated by `fsgg-sdd
  refresh`). The **authored** lifecycle sources — `spec.md`, `plan.md`, `tasks.yml`,
  `evidence.yml`, `charter.md`, `clarifications.md`, `checklist.md`, authored `contracts/` —
  are durable. `validation-report` and `composition-acceptance-result` are already declared
  *sensed harness exceptions*, not catalog artifacts. The taxonomy is therefore **descriptive
  of shipped behavior**, not a new policy invented here.

- **The producer is SDD.** Only SDD can ship the convention (a fragment + a doc); the
  consuming repos adopt it. So SDD sits at the head of the dependency chain, and its slice is
  additive and backward-compatible — it can land before the consumer cleanups.

- **Governance's committed evidence is durable by design and must not be swept.** The
  Governance repo commits evidence *as the audit trail / record of record* — that is its
  purpose. This ADR targets *regenerable process noise*, never the governance record; each
  candidate category is triaged, not blanket-stripped.

## Decision

Establish one shared taxonomy and a positive, role-based gitignore convention. All four parts
are **additive and backward-compatible** — no build, contract, or runtime surface changes.

1. **Canonical durable-vs-regenerable taxonomy, SDD-owned and catalog-derived.** SDD publishes
   the taxonomy as a first-party doc **derived from `release-readiness.json`** and drift-guarded
   — not a hand-maintained second source of truth (consistent with SDD's authored-source /
   generated-view / drift-guard doctrine). The two classes:
   - **Durable (keep committed):** authored lifecycle sources (`spec.md`, `plan.md`,
     `tasks.yml`, `evidence.yml`, `charter.md`, `clarifications.md`, `checklist.md`), authored
     `contracts/`/schemas, and — explicitly — **Governance audit/evidence that is intentionally
     the record of record**.
   - **Regenerable (gitignore):** per-run `readiness/<id>/` generated views, test-regenerated
     baselines/snapshots, diagnostics/log dumps, `nuget-cache/`, and other machine-emitted run
     artifacts.

2. **Ignore transient output by directory *role*, not by per-feature exception.** Repos ignore
   the conventional transient path (the `readiness/`-style role) as one positive rule, retiring
   the re-inclusion lists. A specific piece of evidence that must be pinned as a durable proof
   is pinned **explicitly and rarely**; the default is ignore.

3. **SDD ships the shared gitignore fragment.** `fsgg-sdd init` seeds a **no-clobber**
   `.gitignore` fragment (the same authored-skeleton, `AgentGuidanceTarget` no-clobber class as
   `.fsgg/constitution.md` / `early-stage-guidance.md`), so a scaffolded product ignores
   `readiness/<id>/` **at birth**. Existing repos adopt the identical fragment. (Registering the
   fragment as a governed registry contract is **deferred** — revisit only if fragment drift
   across repos becomes a real problem.)

4. **One-time tree cleanup via per-repo child issues, gated on this ADR.** Each consuming repo
   removes its already-committed regenerable files under its own child issue, linked to #110.
   Scope is the working tree (stop committing + `git rm --cached`), **not** a history rewrite.
   Governance's durable audit evidence is explicitly excluded from any sweep.

## Consequences

Per-repo obligations, sequenced on the Coordination board (Projects v2 #1):

- **SDD (P2, producer — head of chain):** a `specs/073-*` feature delivering the
  catalog-derived taxonomy doc + `init` `.gitignore` seed + drift guard. Ships first; everyone
  else depends on the fragment.
- **Rendering (P1):** collapse the 98-exception list to the single role rule; child cleanup
  issue for the 2,053 committed readiness files.
- **Governance (P3):** adopt the fragment; child cleanup that **preserves the durable audit
  record** (triage, not sweep).
- **Templates (P4):** adopt the fragment; cleanup any committed regenerable composition output.
- **.github (P0):** this ADR; the board epic already exists as #110.

Trade-offs / notes:

- **History is not rewritten.** Already-committed files leave the working tree but remain in
  git history; a full history rewrite is out of scope (coordination + force-push cost far
  exceeds the benefit). The win is bounded, ongoing footprint, not a smaller `.git`.
- **Descriptive, not a behavior change.** The taxonomy formalizes the durable/regenerable split
  SDD already encodes; no generator, schema, or gate changes semantics.
- **Backward compatible.** `.gitignore`-only changes do not affect builds, tests, or published
  contracts; the `init` seed is no-clobber, so existing skeletons are untouched on re-run.
