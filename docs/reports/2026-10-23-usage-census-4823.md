## Method

### Review evidence

The census read each PR's body, its conversation comments and its submitted reviews. No PR in the
population has a submitted GitHub review, and no comment carries a machine-readable review marker.
A PR scores `V` only when one review statement or one dedicated review comment has all three of:

- it names an independent review or critic;
- it gives an explicit verdict: PASS, ACCEPT, APPROVE, or "no outstanding in-scope defects";
- it binds that verdict to the final head SHA. The SHA appears in the same statement, or in the
  same dedicated review comment. Text inside the routine marker does not count. One PR
  (Templates#727) names the head by a 4-character prefix; all others use 7 or more.

Every PR whose record mentions a review was adjudicated by hand against these rules. Every
other PR scores `U`. Each unsampled row carries one of these reasons:

- **independent verdict stated; head not named:** for example "Independent exact-head review
  passed" with no SHA;
- **verdict recorded at earlier head `<sha>`:** the verdict binds a head before the final one;
- **exact-head review with no explicit verdict, or with independence not stated:** #4722,
  Rendering#1456, Coordination#1039;
- **no independent verdict in the PR record:** this includes one PR that states no independent
  review was performed (#4749), and one that keeps its review private (#4774).

Reviews recorded only in linked issues or in private custody are not visible to this census.
They count as unsampled.

One account authored, merged and posted every review record for all 134 PRs. Review
independence is therefore as the record asserts it. The census cannot verify it from GitHub
identity.

### Required checks

Required contexts are the union of the base-branch ruleset `required_status_checks` and classic
branch protection. Both were read at census time. For each required context, the census took the
latest check run or status on the final head.

- These are the rules at census time. Changes to the rules during the window are **Unknown**.
- FSBarV2 has no required checks.
- For the private repository, both the rules and the head checks are unreadable with the census credential, so
  its row is **unknown**.
- Rendering#1464 records the required `Deterministic gate` and `API compatibility gate` as failed.
  That PR was admin-merged with a recorded bypass.

### Actions machine time

1. The census listed all workflow runs created since 2026-10-15 in each population repository:
   27,558 runs in total. Days at the listing cap were split into hourly slices.
2. Each run is assigned to at most one member:
   - **PR phase.** The run's `head_sha` is one of a member's commits or its final head, and the
     run was created at or before that member's merge. Stacked PRs can share commits. In that
     case the run goes to the member whose head branch (or `refs/pull/<n>/head`) matches the
     run's `head_branch`. Failing that, it goes to the member that was open when the run was
     created. A run that matches neither belongs to another PR and is excluded:
     118 runs, all on commits that .github#4711 shares with
     an earlier PR from another branch. The listing returned no native `pull_requests` links for
     these merged PRs, so the census does not use links.
   - **Merge commit.** The run is a `push` run on the member's merge SHA.
     759 other runs on merge SHAs were excluded, because the merge
     did not cause them: 549 `issues`, 130 `schedule`,
     68 `workflow_dispatch` and 12 `dynamic`.
3. For every matched run, the census called the Jobs API `GET /actions/runs/{id}/jobs?filter=all`
   (all attempts) and summed `completed_at − started_at` per job.

Assignment is exclusive, so per-member figures add up to the totals.

What these figures are not:

- They are job wall time, not billed minutes. Billing rounds per job and applies runner
  multipliers.
- They do not cover deleted runs.
- They do not cover runs on force-pushed heads, because those SHAs are no longer in the PR's
  commit list: 36 `pull_request` runs on member head branches inside the open interval (33 on
  .github#4806, 3 on Coordination#1048) are uncounted.

Runs whose jobs could not be read would be marked `unread` in the member rows; there are
0. Nine reads first failed with HTTP 502 and succeeded on retry. Every matched run and
job was `completed` when read, and jobs without both timestamps number 0. Every
job ran on a GitHub-hosted label (`ubuntu-latest` or `ubuntu-24.04`); 50 skipped jobs carry no
label.

### Native usage

Admitted reader: the source-built `fsgg-coord-engine` CLI at `.github`
`61526e947ff595c5eb416efd810ce3c1348bedc5`
([#4802](https://github.com/FS-GG/.github/pull/4802)). It was built read-only, outside the
repository, for this census only.

- **Command.** The reader ran once per file on every retained transcript on the coordinator
  host:
  - 164 Claude Code JSONL files (3 main sessions and 161 subagent transcripts) under the single
    Claude configuration home;
  - 50 Codex rollouts under the single Codex home.

  Each run used:

  ```
  fsgg-coord-engine telemetry usage collect <claude|codex> --session-file <file> \
    --task census-4823 --all-responses \
    --since 2026-10-19T18:19:36Z --until 2026-10-23T00:00:00Z \
    --coord-version 61526e94 --sdd-version unknown --contracts-version unknown \
    --receipt-store <scratch dir> --format csv --output <scratch file>
  ```
- **Receipts.** The usage receipt store was a scratch directory. No receiver, telemetry store or
  UTEL database was opened.
- **Counters.** Counters are the reader's response-level columns:
  - `input` includes cached input and cache-write input;
  - `total` is `input + output`;
  - `reasoning` is reported as the provider supplies it.
- **Duplicates.** A resumed Claude Code session copies earlier records into the new transcript.
  313 responses appeared in two sessions with identical counters. They are counted once, by
  provider response ID.
- **Attribution.** A response is attributed to a member only when both hold:
  - the `gitBranch` on its own transcript record equals the PR's unique head branch;
  - its timestamp is no later than the merge.

  The strict reader does not emit branch or cwd. The join keys therefore come from a separate
  census-local parser. It parses each transcript record as JSON and keeps only the session,
  agent, sidechain flag, branch, cwd and message ID. For Codex rollouts it keeps the
  `session_meta` identity, cwd, branch and source, and each turn's cwd. It retains no content.
  All counters come from the strict reader alone.
- **Unattributed.**
  - Codex rollouts record only `main` and the main checkout as their working directory.
  - No PR text in the population cites a session or thread identity.

  So all Codex usage, and every Claude Code response on `main`, is unattributed.

## Gaps and Unknowns

- **Other hosts, including the Home agent:** usage **Unknown**. This census did not read the
  Home UTEL store, and it did not need any data that only Home can read.
- **Billed cost:** **Unknown**. No list-price estimate is given: the census has no verified
  list prices for the recorded model IDs.
- **Withheld Claude Code subagent transcripts:**
  - 9 subagent transcripts have a response with no completed usage record. The reader withholds
    their totals, so those tokens are **Unknown**.
  - 2 subagent transcripts mix session identities and were refused.
- **Join parser:** the attribution join keys come from a census-local parser, not from the
  admitted reader. Counters are unaffected.
- **Pruned transcripts:** transcripts and rollouts deleted or pruned before the census are
  **Unknown**.
- **Attribution:**
  - Per-PR token figures cover only the 3 branch-joined PRs.
  - Per-issue tokens and reviewer or critic tokens are not separable.
  - Subagent transcripts on `main` remain unattributed.
- **Required checks:** these use rules read at census time. The private repository is unreadable.
- **Review:** independence rests on the record's own assertion. Reviews held only in private
  custody or in linked issues count as unsampled.
- **Elapsed time:** this is not idle time or critical-path time. No savings or efficiency claim
  follows from it.
- **Project 3:** items removed from the project before the census, and reopened items, are not
  in the population.

Actions runs listing and Jobs API; repository rules and branch protection; Project 3 items; and
issue `ClosedEvent` closers. The scripts and private per-response rows stay in fdev scratch

column/row tables. It holds no session identities and no transcript content.
