## Process problems we can fix

**Release qualification missed its own environment prerequisites.** SDD's immediate public install initially could not resolve the just-published package; a later fresh install succeeded. Its separate qualification then reached a different concrete defect: missing Java/Apalache setup before Q2/Q3. The SDD owner is reusing the accepted pinned setup in the existing repair PR. Preserve publication as delivered, retain both original failures, and qualify public use after the workflow repair. A package re-publication would add risk without addressing this cause.

**Historical fixtures were coupled to active tool choices.** Game's current compiler upgrade exposed old Core/Fable expectations and a frozen WASM builder requiring its historical Rust version. The Game owner is separating explicit historical roles from current identities, preserving original artifact bytes and strict guards. This avoids a misleading choice between silently rewriting evidence and blocking every active upgrade. Full runtime qualification is still the decision boundary.

**Evidence and admission steps caused avoidable serial waits.** Several ordinary source diagnostics paused for repeated approval, and later linkage discovery triggered extra metadata CI. Root is carrying existing authorization forward within concrete resource bounds and checking supported linkage earlier. Those changes should reduce waiting, but no elapsed-time or token saving is measured. Unknown sends, publication and genuine access limits still require their original safeguards.

**Shared source overlap can waste qualification.** Enrollment, continuation tooling and other hub changes overlap generated Atlas/catalog surfaces. The coordination owners held obsolete-base launches, composed the accepted union and retained unchanged implementation evidence. Continue that approach: one accountable integrator, a current base and exact changed-source joins, rather than duplicate full local validation. The cost benefit is plausible, not quantified.

**Worker interruption required recovery.** Several workers hit usage limits. Replacements recovered committed source, original run identities, journals and bounded operations instead of restarting them. Recovery succeeded, but its overhead is not free or measured. Keep native owning records current during normal boundaries; planning Status and worker count remain different populations.
