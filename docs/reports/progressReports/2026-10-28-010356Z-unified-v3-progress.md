## Process problems we can fix

- **Late composition keeps revealing interface defects.** Actual execution exposed clock, role, producer/consumer, filesystem, permissions and file-descriptor custody mismatches after substantial component work. A missing observation method and concurrent census behavior were corrected, but the latest complete attempt still stopped before the workload. These are owned internal defects, not external supply failures. Root owns freezing the smallest joined contract; the same integrator owns fixing the next determining failure through the actual production entry. Reconsider readiness only after a complete fresh trace and a precise remaining-gap list, followed by whole-candidate review.
- **Some failed observations misdescribe the underlying event.** The latest source observer labeled an exited child's empty command line as argument drift. The preparation process actually returned exit 3 with empty stderr; that is not evidence of an alarm or forced kill. The integrator is observing the actual exit context rather than inferring it from the secondary symptom. Earlier cold process/group observations and real waits establish only that source attempt's cleanup scope; they do not establish production cleanup. Retain the original result and correct the diagnostic interpretation at the owning issue.
- **Freshness and test packaging caused avoidable repetition.** Periodic full runs exposed contamination from a parent test module that exceeded the existing input cap. The maintained source fixture/bootstrap/runtime closure was corrected without raising the cap. Root has also required fresh recipe hashes and live resource facts for each retry, retaining old inputs only as reference. The practical improvement is to batch immutable closed-input checks while keeping final launch, clocks, resources and cleanup fresh. The final full path remains mandatory; no earlier pass transfers automatically.
- **Coordination can become another repeated workload.** Unchanged waiting, repeated explanatory reports and growing guard assembly consume attention without producing a usable BAR boundary. Root owns result-triggered updates: report a determining failure, changed supplier fact or meaningful acceptance, then return to the same execution queue. This does not remove required checks or justify hiding failures. It reduces duplicate narration without adding a ledger or telemetry gate; the benefit is plausible, not measured.
- **Knowledge capture must follow the new evidence.** Protected Atlas records now preserve recovery, custody and early-integration lessons, but later replay, stream, clock and horizon findings are not yet captured. Root retains that capture gap for the next meaningful delivery. Keep the existing owning issue authoritative until concise, cited supersession records are ready; do not copy logs or private payloads into public knowledge.

## Blockers the current process cannot resolve

Actual native qualification still needs Host-enforced capacity and its finite complement, the genuine PID 1 interface and the real image/provider inputs. Home supplies host facts and custody; Root decides whether their evidence admits the selected operation. An unassembled internal source interface remains Root's implementation responsibility, even when its eventual runtime needs those suppliers. More component tests cannot establish exclusive resources or a genuine image.

The product builder and accessibility runtime must be assembled and qualified by their existing owners. Two-machine acceptance needs genuinely independent allocations, preserving the recorded independence requirements. Unity requires the real operator, license and Editor; receiver and application acceptance require their custody holders; trusted publishing and protection access require the accountable account owner. There is no supported substitution of source checks for these capabilities. Unrecoverable original bytes and receipts cannot be recreated by retrying, and historical uncertain effects remain uncertain.

These external dependencies have no defensible completion date. They should not conceal the immediate internal work: a complete source-controlled execution and cleanup trace is still missing before native admission can be assessed.
