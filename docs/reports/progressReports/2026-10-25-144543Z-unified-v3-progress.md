## Process problems we can fix

**Repeated approval and preparation have a concrete replacement.** The accepted [finite-envelope decision](../../adr/0096-proportionate-verification-and-unrecoverable-holds.md) binds source, inputs, resource limits and the ordered sequence once. Two actual Home GitHub envelopes completed with one apply each, in approximately 150 and 42 seconds, with independent cold readback inside their original limits. This demonstrates useful bounded delegation without success-by-success coordinator approvals. Root and execution owners should use that admitted pattern for complete, reviewed sequences while preserving independent step clocks, original failures and no automatic retries. Reduced approval churn is demonstrated; token savings are unmeasured.

**Capability assumptions sent investigation toward the wrong credential.** Home's existing OAuth/keyring capability supplied private Checks that Root's fine-grained token could not read. The earlier recommendation to depend on Root's Checks UI was withdrawn. The successful route used neither a new token nor a new App. Private policy responses remain unavailable when access returns 403; they cannot be treated as empty policy. Root owns early endpoint-specific credential, policy and workflow preflight. Reconsider only when the actual capability or determining source changes, rather than repeating broad permission discussion.

**Late integration continues to expose real coupling defects.** Three concrete engine-mode mismatches needed source repairs; the newest local controls passed, but its CI was still pending at cutoff and inherits no earlier result. Constructors and callback tuple checks do not establish callback settlement or native cleanup. Home retains the initializer/guard/collector/retirement implementation, with a 15:00 UTC code-or-gap checkpoint and a 15:30 integrated-source target. Those are source checkpoints, not native completion estimates. Root should inspect the smallest complete runtime prefix before adding all bake members, avoiding another large assembly whose first real execution discovers basic coupling.

**Acquisition repair succeeded, but export still needs its full closure.** The first Skopeo signature-reader refusal was an armored-keyring format mismatch. A separately reviewed preparation used the same frozen package and trusted keys, staged signed files and independently settled its scope. That removes the acquisition obstacle without changing host trust or installing packages. Exact-source inspection then found a hardcoded temporary path and fallback behavior that private staging alone does not cover. Root and Home own the remaining dependency, backing, helper and cleanup closure; operational export remains unselected. The original refusal is retained, rather than relabeled as a transient success.

**Diagnostic filtering hid the evidence needed to explain BAR's failure.** The owner repaired the narrow public filter and preserved the original deadline failure. That is productive changed-input validation, not grounds for rerunning the unchanged old operation or increasing its budget. The existing deterministic watch continues; Root oversees its result after the source owner's capacity failure. The cause remains unknown until the actual diagnostic result supports a conclusion. More reporting workers or duplicate watches would add coordination without supplying that evidence.

## Blockers the current process cannot resolve

Several missing capabilities are still supplier facts rather than scheduling problems. The reusable builder needs actual supported glibc 2.44 tools, native ABI, namespace, backing and capacity proof. Existing Home Arch plus pinned tools and the qualified supervisor is the preferred candidate; a new image or private caller is not inherently required. Home supplies those facts after the primary runner path. The declared sequential maximum already exceeds the old two-hour allowance before preparation, so that allowance cannot simply be reused.

Native accessibility separately needs the assembled Noble desktop, input method, assistive-technology runtime and actual portable game artifact closure. The facility/operator and source owner must supply this evidence; neither DOM tests nor an assumption that managed code is portable can substitute. This route is unassembled, not proved impossible.

Unity licensing/operator participation, Governance physical proof, independent machines and original unresolved effects retain their named suppliers. Additional agents cannot manufacture legal permission, physical evidence or original custody. Keeper's restart witness specifically waits for the next normal reboot. There is no supported dedicated-reboot workaround within the selected scope, and no reliable finish date for these dependencies.
