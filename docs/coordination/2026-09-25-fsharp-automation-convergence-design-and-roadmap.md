# F# automation convergence for the GitHub Substrate v2 fleet

**Status:** proposed, 2026-09-25. This design plans source work and receiver adoption; it does not accept a GS2 unit, change a protected receipt, or authorize an administrative effect. The [17-repository review](../reports/2026-09-25-fsgg-fleet-code-architecture-review.md) records the evidence and limitations. The [V2 roadmap](../github-substrate-v2-roadmap.md) remains the cutover authority. The [fleet cutover design](2026-08-25-github-substrate-v2-fleet-cutover-design.md) governs candidate inputs, qualification, freeze, and rollback.

## Decision and scope

Move deterministic policy, manifest, projection, and artifact logic from Python or shell into a typed F# command owned by the repository that owns the behavior. Preserve small platform launchers, independent qualification oracles, generated receiver examples, and shell operations that depend on operating-system semantics. A source extension alone is no reason to port a file. Each replacement needs a versioned contract, an independent refusal test, an installed consumer proof, and removal of the displaced authority after its compatibility window.

This is a **parallel preparation track**, not an added GS2-10 or `OpenV2` exit gate. A selected change to a kernel, provider, registry, workflow, receiver, package pin, or settings profile must finish and stabilize before GS2-10 or wait until `OperatingV2`. A change after candidate freeze creates a new candidate and a complete Q0–Q7 run; it cannot enter the GS2-11–GS2-12 closed-fleet window. The only prefreeze work that can block cutover is a separately demonstrated defect in an existing required gate or a selected candidate input, dispositioned under the governing roadmap.

**Current selection:** no optional F# port is selected for the GS2-10 candidate while GS2-09.7/09.9 and OperatingV1 effect admission are unfinished. FSC-00 census, current-source reconciliation and read-only parity can run now; source repairs [#3696](https://github.com/FS-GG/.github/pull/3696) and [#312](https://github.com/FS-GG/FS.GG.Audio/pull/312) follow their normal owner gates. A later prefreeze selection needs an exact owner contract, installed proof and a recorded candidate-input disposition. Otherwise all producer publication and receiver flips in this track wait until `OperatingV2`.

The [2026-09-04 F# telemetry and roadmap-projection design](../reports/2026-09-04-fsharp-roadmap-telemetry-and-projection-automation-design.md) is a prior proposal, not a current work list: its four named Python helpers are absent from the reviewed tracked main tree, while `Telemetry.fs` and `RoadmapWorkUnit.fs` already provide F# surfaces. First reconcile its remaining requirements and accepted evidence against current source. Telemetry Contracts and Store reference the Coord Core assembly; Store compiles `TelemetryStoreApplication.fsi/.fs` from a historical Coord CLI source path into the Store assembly. Host references Contracts and Store, **not the Coord CLI binary**, and its package includes Core. These concrete dependencies require a V1-only symbol/package inventory and qualified retain-or-extract decision at Q9; GS2-14 does not prescribe deleting all Coord projects. Any new enduring policy must avoid V1-only dependencies. [Standalone Host](../roadmaps/2026-09-09-190726-standalone-telemetry-host-and-orchestration.md) and [dashboard](../roadmaps/utel-telemetry-dashboard.md) work keep their existing owners; this plan starts no competing telemetry implementation. [V2-CI-I1](../roadmaps/v2-ci-i1-unattended-credential-execution.md) owns unattended credential execution; this plan does not substitute a language port for its protected grant, OIDC, one-attempt, or readback controls.

## Architecture of a replacement

```text
versioned source data / GitHub observations / package bytes
                 |
                 v
       owner-specific strict adapters
                 |
                 v
       pure F# policy or reduction
                 |
                 +--> typed verdict + stable machine evidence
                 |
                 v
       existing authorized effect boundary
                 |
                 v
       independent protected readback
```

- **Producer ownership.** SDD owns generic contract/artifact primitives; `.github` owns organization registry and policy in a tooling package without V1-only runtime dependencies; Coordination owns V2 execution; Templates owns provider composition; product repositories own product policy. Sharing a generic parser or archive primitive does not transfer a repository's decision authority. Inventory Coord dependencies before Q9 and retain non-V1 code only under an explicit qualified disposition.
- **Compatibility.** Freeze the current successful bytes or semantic fields and the exact negative corpus before porting. Differences in canonicalization are policy, not formatting: Rendering's skill stager folds CRLF and removes a BOM, while Game's removes the BOM without that CRLF fold. Version those policies separately.
- **Effect boundary.** A new F# reducer should be pure or read-only first. Publishing, installation, GitHub mutation, credential use, and release remain behind the existing scoped gate. Keep shell for process environment, `exec`, packaging, and platform probes when replacing it adds no policy clarity.
- **Independent evidence.** A Python test that attacks a F# implementation can be valuable precisely because it does not share the parser. Do not delete it solely to achieve language uniformity. Keep a separately authored black-box oracle for safety-critical predicates.
- **Installed bytes.** Qualify the package/tool restored by a clean receiver, not just a source-tree `dotnet run`. Publish producer before flipping a receiver, pin exact artifact identities, then retire old logic after the named compatibility window and an absence check.
