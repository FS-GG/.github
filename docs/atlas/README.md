# Atlas

Atlas is FS.GG's primary curated project-knowledge archive and retrieval path.
Reviewed, immutable records live in Git; SQLite FTS5 is a rebuildable local index.
The [Atlas skill](https://github.com/FS-GG/.github/blob/main/.agents/skills/atlas/SKILL.md) owns retrieval and capture guidance,
including the [record contract](https://github.com/FS-GG/.github/blob/main/.agents/skills/atlas/references/records.md).

Search from this checkout:

```bash
python3 .agents/skills/atlas/scripts/atlas.py search 'governance dependency'
python3 .agents/skills/atlas/scripts/atlas.py get platform/dependency-direction
python3 .agents/skills/atlas/scripts/atlas.py validate
```

Repository owners can add their own `docs/atlas` archives and aggregate them with repeated
`--archive` arguments. This shared corpus records the component boundaries and cross-repository
contracts, plus selected reusable BAR knowledge. Its citations pin the inspected revisions; query
results are historical knowledge until verified against the relevant source and live state.

Keep ADRs, registries and owner plans canonical. Atlas stores a concise finding and its relevance,
not duplicate authority. Capture decisions, lessons, incidents and open questions; exclude logs,
bulk reports, full source, binaries, private evidence, credentials and runtime assets. Archive
payload validation permits only catalog, immutable records and this short readme. Combined archives
warn at50MiB and refuse above100MiB. Individual records refuse above32KiB; aim for a few KiB.
SQLite overhead is measured separately (300MiB safety ceiling), and retrieval refuses over64KiB.

The seed is generated byte-identically into both skill roots for offline package consumers. It is a
snapshot of this archive, not independently edited knowledge. `tests/atlas/check.py` verifies
correspondence, guidance, budgets, baseline history and executable retrieval behavior. Python3.9+
with SQLite FTS5 is sufficient; no game, CLR, account, network or runtime service is needed.

The source manifest stages Atlas as an always-materialized driver. Publishing/updating the Drivers
package and existing consumer installations remains a separate delivery boundary; this source
change makes no fleet installation claim. Operator guidance and programme/roadmap hooks apply
immediately in this checkout. Framework repos using only Kit need a deliberate Atlas delivery/update,
rather than a false claim that a new driver was already installed everywhere.

## Coverage and freshness

The [2026-10-14 project audit](https://github.com/FS-GG/.github/blob/main/docs/reports/2026-10-14-atlas-project-audit.md)
reviews all24 organization repositories and the externally rostered `EHotwagner/S.I.R.`.
It follows selected implementation, contracts, dependency graphs, workflows and owning
acceptance evidence beyond the initial README-based seed. Empty repositories are
reservations, and public records about private products retain public owning-plan scope.
Private findings live in a separate access-restricted archive, never in this seed.

The archive preserves the original records and explicitly supersedes inaccurate
summaries. Records distinguish implementation, public package availability, installed
acceptance and current operations. Historical citations authenticate the source bytes;
they do not make a stale interpretation current. Open questions remain searchable.
The original dependency seed covers29 declared contracts without becoming a version registry.

The [knowledge lifecycle](https://github.com/FS-GG/.github/blob/main/.agents/skills/atlas/references/lifecycle.md)
requires retrieval before substantial work and reconciliation before delivery or handoff.
Memory stores repository and stable Atlas-ID pointers rather than changing project facts.
Use source and live systems to verify current claims, then capture a concise cited change,
explicit supersession/conflict, or an owned gap. There is no unattended freshness guarantee.
