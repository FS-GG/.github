# Temporary Unified Roadmap driver

The repository-owned [work-programme](../../.agents/skills/work-programme/SKILL.md) skill replaces
`work-unified-roadmap` for this programme. It keeps the parent focused on lane frontiers, integration
and decisions; implementation owners retain detailed source investigations and evidence. It is temporary,
does not change generated-workspace defaults, and needs no package release or permanent Host rollout.

The dependency-free F# adapter supplies advisory frontier decisions, pinned bounded packets, streamed
artifact hashing, retained input/result files and private operation measurements. It does not launch
agents, merge PRs, execute workloads or issue acceptance authority. Existing admission, routine delivery,
qualification-selection, telemetry and operation safeguards remain in force. Byte equality is distinct
from signatures, semantic acceptance, complete artifact inventories and process custody.

Acceptance is intentionally short: one offline FSI suite with 31 cases, an actual CLI canary using the
new skill/helper bytes, and the repository's normal skill/catalog/mirror/selector checks. Source delivery
lands as one routine PR. The first separately requested programme run is the operational trial; no extra
rollout programme or live workload is required merely to install the skill.

The focused suite covers independent lanes, sequential reservations, repository-scoped paths, stale/future
observations, retained unreadable owners, unknown/failed operations, same-chain owners, pending validation,
late disputes, projection holds, existing PRs, repository PR capacity, unknown capacity, dependency cycles,
unsupported globs, complete mandatory instructions, missing/excerpted/oversized instructions, real file
drift, optional omission, artifact drift, missing artifacts, links, duplicate/unknown JSON and replay.

Both `.agents` and `.claude` carry the same complete skill tree; the old directories and catalog entry
are removed. Planning/audit references are preserved under the successor. Current roadmap entry points
and `work-roadmap` callers select the new name. Historical reports, handoffs and old consumer acceptance
keep their original identities in protected history; the new skill never relabels those native results as
its own acceptance. Resume from current default-branch guidance rather than executing an old handoff's
retired entry-point link. Existing active workers keep their owner/attempt identities and are not relaunched.

The triggered entry point falls from 21,213 to 8,599 bytes (59.5% reduction). That is a static byte
comparison, not a token, total-context or compaction result. The first private CLI run retains an expected
stale-pin failure alongside later final-pin success. Actual compiler/CLI startup is measured separately
from helper execution; native tokens remain unknown and compaction remains not observed.

On each requested programme window, use the existing telemetry plus `report PRIVATE_ROOT`. Inspect expanded
parent context, refusal reasons, duplicate retrieval and helper timings. Repair demonstrated problems on
the same owning branch/PR, preserving all substantive acceptance, original lineage and model routes.
Charge debugging and specialist work to that item; never infer usage from bytes or elapsed time. Retire
the skill and adapter when this programme ends or a qualified successor replaces them.
