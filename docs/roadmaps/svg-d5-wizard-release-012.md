# SVG Release D.5 wizard 0.12.0 publisher rail

This is the successor to the GS2-08.9-sealed `release-new-sdd-workspace.yml`. That workflow remains a local pack demonstration. This rail is for `FS.GG.NewSddWorkspace` 0.12.0 only; source PR #3947 and the Templates 0.15.0 public package must land before it runs. It does not activate the D.5 default join by itself.

The candidate workflow dispatches on the current protected `.github` main SHA. It refuses an existing `new-sdd-workspace/v0.12.0` tag or either feed version, runs the focused wizard fixture, packs once with `RepositoryCommit` equal to that SHA, validates the package's nuspec commit, and retains the original nupkg, manifest, and package evidence in one Actions artifact. Candidate permissions permit reads only. Its package archive hash is exact; `producerPayloadSha256` normalizes feed-added signature differences, retaining the nuspec source commit.

The separate publisher dispatch defaults to read-only preflight. It accepts the successful first-attempt candidate run ID, artifact ID, and Actions archive SHA-256, checks native API run/artifact identity and safe artifact members, and re-verifies the original nupkg. With `publish=true`, the `release-successor` environment and sole operator gate admit each effect against live main and the protected journal ref `fsgg/v2/journal/release/svg-d5-wizard-012` in `FS.GG.Coordination.Authority`. The ordered effects are exact source tag, draft release, GitHub Packages, nuget.org, original package asset, manifest asset, dual-feed observation journal asset, and promotion. Both feed readbacks must match the producer payload; the journal records each feed's observed archive hash. Promotion also requires a clean `dotnet tool install FS.GG.NewSddWorkspace --version 0.12.0` from the public nuget.org source and a working `new-sdd-workspace --help`. A stopped run resumes only from protected intent and observed effects; it does not repeat an uncertain write.

Before dispatch, register nuget.org Trusted Publishing for owner `Paradigma11`, package `FS.GG.NewSddWorkspace`, workflow `release-new-sdd-workspace-successor-publish.yml`, and environment `release-successor`; verify the ordinary ledger App can write that protected journal ref. Run publisher preflight on the candidate while main still equals its source SHA, then use the same candidate for the publish dispatch. A main advance after candidate creation requires a fresh candidate for a fresh publication. After the public tool and Templates 0.15.0 are both available, run the separate clean public D.5 receiver proof before changing any default join.

The preflight deliberately keeps inexpensive static identity and artifact checks ahead of the network and tool install; it reuses the tested protected-journal executor rather than creating a second state machine. Local fake-provider tests cover effect ordering, denied admission, delayed readback, artifact binding, source-commit refusal, dual-feed journal readback, and the public-install promotion gate. The full source fixture and one real 0.12.0 pack/manifest check are the proportional qualification before a native candidate run.
