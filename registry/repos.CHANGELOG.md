# Repo roster changelog

Reverse-chronological log of changes to [`repos.yml`](repos.yml) — the FS-GG org repo roster (the
single authoritative list of framework repos the org fabrics iterate, ADR-0019). Its human
projection is [`../docs/registry/repos.md`](../docs/registry/repos.md).

**Protocol.** Mirrors [`CHANGELOG.md`](CHANGELOG.md) (the `dependencies.yml` log) and
[`skills.CHANGELOG.md`](skills.CHANGELOG.md): every change to `repos.yml` **prepends one dated entry**
at the top of the Entries list below (newest first) and sets the file's `updated:` date to match.
Entries follow the same loose `HEADER (owner; refs): body` grammar — name the repo id(s) and/or the
`receives` capability touched, the owner, and the issue/ADR refs. Adding or retiring a repo, or
changing a repo's `receives`, is a changelog-worthy roster change; bumping the kit `sha256` after a
skill/client edit is too.

`repos.yml` is validated by [`../scripts/repos.sh validate`](../scripts/repos.sh) (schema, the
single-authority invariant, the `receives` vocabulary, and content-addressed kit digests).

## Entries

- **2026-07-09** — ADD repo **`audio`** (`FS-GG/FS.GG.Audio`, role `framework`, `receives: [labels, coordination-kit]`) — the org's **seventh repo, never rostered** (owner github; refs ADR-0023, ADR-0019). `FS.GG.Audio` was transferred into the org and registered in [`dependencies.yml`](dependencies.yml) as a contract owner (`fs-gg-audio`, consumed by rendering) when it cut `0.1.0-preview.1`, but nobody added it to **this** roster. Consequences, all silent: `coordination-propagate` never opened a kit PR against it, `apply-labels.sh` never gave it the shared labels, and — because the coherence gate's `--repo` roster check exits 0 for a non-receiver — **no gate could ever report the absence.** Its kit is *missing*, not drifted: no `scripts/fsgg-coord`, no `cross-repo-coordination` or `intra-repo-parallel-work` under either skill root. Found while reconciling kit drift across the org after the SDD `v0.9.0` release; the other five receivers had merely drifted (their propagate PRs sat open and unmerged) and were re-synced by merging those. **No `schemaVersion` bump** — a row, not a shape change. `scripts/repos.sh validate` → green; projection [`../docs/registry/repos.md`](../docs/registry/repos.md) updated in the same change. Audio still needs its own thin `coordination-coherence.yml` caller before the pull gate applies to it — `coordination-sync` manages the skills + client, not workflows — and `coordination-propagate` fires only on pushes touching kit paths, so this roster row does **not** self-trigger it; dispatch the workflow, or seed the kit with `scripts/coordination-sync <checkout>`.

- **2026-07-09** — Coordination-kit `fsgg-coord` + `cross-repo-coordination` sha256 bumped (@.github; #259, #254): `lint`'s `EPIC-NO-CHILDREN` invariant is now scoped to **open** epics. It had fired on any `[epic]` card with zero sub-issues regardless of state, which on the live board meant three errors against three **closed** epics (`.github#234`, `FS.GG.SDD#159`, `FS.GG.SDD#160`) — keeping `lint` permanently red and burying its one genuine finding (`EPIC-DONE-OPEN-CHILD .github#235`). Neither harm the rule names survives closure: rollup is how an epic *reaches* `Done`, and `next` hands out only open `Ready`/`Backlog` cards. `EPIC-DONE-OPEN-CHILD` is deliberately left unscoped — a closed epic over an open child is the sharpest form of *that* bug. Re-digested client `220e8822…` → `447a330c…` and skill `2da47871…` → `436357f7…`. Propagates to `coordination-kit` receivers via the `coordination-coherence` gate.

- **2026-07-09** — Coordination-kit `fsgg-coord` sha256 bumped (@.github; #257, ADR-0021, ADR-0027): in-flight work is now found by its **claim marker**, not the board's `In progress` column. `claim` writes that column strictly best-effort — a Projects v2 5xx is swallowed, and an item never added to the board has no column at all — so `who`/`reap`/`inbox` went blind to real claims, and `batch` never RESERVED an off-board claim's `Paths:` touch-set, which let the scheduler double-book overlapping work. `active_claims` now unions the column (the only source that can report `UNCLAIMED`) with every open issue carrying a live marker, found via a paginated, uncached issue scan pruned soundly on `comments > 0`. `reap` also stopped reporting a board reset it never performed.
