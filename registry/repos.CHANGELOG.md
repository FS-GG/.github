# Repo roster changelog

Reverse-chronological log of changes to [`repos.yml`](repos.yml) — the FS-GG org repo roster (the
single authoritative list of framework repos the org fabrics iterate, ADR-0019). Its human
projection is [`../docs/registry/repos.md`](../docs/registry/repos.md).

**Protocol.** Mirrors [`CHANGELOG.md`](CHANGELOG.md) (the `dependencies.yml` log) and
[`skills.CHANGELOG.md`](skills.CHANGELOG.md): every change to `repos.yml` **prepends one dated entry**
at the top of the Entries list below (newest first) and sets the file's `updated:` date to match.
Entries follow the same loose `HEADER (owner; refs): body` grammar — name the repo id(s) and/or the
`receives` capability touched, the owner, and the issue/ADR refs. Adding or retiring a repo, or
changing a repo's `receives`, is a changelog-worthy roster change; bumping the kit `sha256` after a
skill/client edit is too.

`repos.yml` is validated by [`../scripts/repos.sh validate`](../scripts/repos.sh) (schema, the
single-authority invariant, the `receives` vocabulary, and content-addressed kit digests).

## Entries

- **2026-07-09** — Coordination-kit `fsgg-coord` + `intra-repo-parallel-work` sha256 bumped (@.github; #277, ADR-0021, ADR-0027): a **quoted `Paths:` line was read as a declaration**. `paths_from_body` grepped `^[[:space:]]*[Pp]aths:` across the *entire* issue body, **fenced code blocks included**. So an issue that merely *quotes* a touch-set — in a reproduction, in prose, in a suggested `widen` command — silently acquired it as its own; and because every match is unioned, a body carrying a real declaration *and* a quoted one reserved both. (The union is not the defect and is kept, deliberately — see below; reading the *quotation* is.) This is the sibling of #273, one turn further in, and strictly the more dangerous of the two: an **unmatchable** token (`**/foo`) reserves *nothing* and is detectable because no token can match, which is why #273 could be refused by naming it; a **fabricated** token reserves the **wrong files**, confidently, and passes every check #276 added, because `invalid_paths` sees only well-formed exact paths. #261 is the live instance — its only `Paths:` line sits inside a fence quoting `FS.GG.Rendering#186`, so it reserved *Rendering's* files and **none of the file it edits** (`scripts/fsgg-coord`); #276 rejects it only *by accident*, via a stray `**/packages.lock.json` in the quote. It is a bug that cannot be written up without triggering it: #273 infected itself with its own reproduction.

  **Fixed by stripping code blocks before scanning** — fenced (` ``` ` and `~~~`, honouring the fence character, its length, and markdown's ≤3-space indent bound) and indented, since markdown's own rule settles that case: a `Paths:` line indented 4+ spaces *or a tab* is a code block, so a declaration is one indented at most 3 (a list-nested declaration keeps working). That last part is a **behaviour change** — the old `^[[:space:]]*` matched a tab-indented line — and it fails *closed*: such an item now declares nothing and is loudly refused as undeclared rather than mis-scheduled. A body whose only `Paths:` line is fenced likewise declares **nothing**, the fail-**closed** direction epic #266 requires: unschedulable beats mis-scheduled.

  **What survives the strip is UNIONED, not `head -1`ed — deliberately against #277's suggested fix**, and this is the substantive judgement in the change. Both stop a *fenced* quote from widening a real declaration, but only because the strip already deleted it; they differ on a quote that **escapes** the strip — a bare one at column 0, which #277 itself records as how "#273 infected itself with its own reproduction". Take the first line and you reserve the **quotation** and silently **drop the real declaration beneath it**: *under*-reserving, so two workers are told `DISJOINT` on a file they both edit. That is ADR-0021's own failure mode — precisely what this file exists to prevent, and what a fix for #277 must not reintroduce. `main` unions today and therefore over-reserves, which is safe; `head -1` would have made this PR a net regression on the one axis that matters. Unioning keeps the **superset**: the cost is a false `OVERLAP` — loud, investigable, spending only parallelism. Over-reserve on ambiguity; never under-reserve. All three tests #277 asked for pass under the union (its own quotations are fenced), so the deviation is invisible to the issue's acceptance criteria and visible only in the failure mode. `widen` **collapses** the duplicates to one, keeping reader and writer coherent — replacing only the first would leave the rest reserving their old tokens, i.e. a widen that did not widen to what it printed.

  **The writer had the same bug, found in review and fixed here.** `widen` rewrote the first `/^[ \t]*[Pp]aths:/` line *anywhere* in the body. Had only the reader learned about fences, `widen` would have patched a quotation inside a code block, left the real declaration standing, and printed a confident `widened … → Paths: …` for a touch-set the reader would never see — and on a body whose only `Paths:` line is fenced (the #261 shape, i.e. exactly the item a worker is trying to *repair*), it would overwrite the quote and leave the item still declaring nothing. Reader and writer now share one `FENCE_AWK` tracker and one `^ {0,3}[Pp]aths:` bound, so `widen` patches precisely the line `paths_from_body` reads, and **appends** one when no declaration exists.

  **Two more the guard nearly shipped**, both in that new writer, both now pinned by an assertion that fails without its fix. **(i)** An **unclosed fence** swallows the rest of the body, so there is no declaration to patch and `widen` appends — *into the still-open fence*, where the reader cannot see it. It printed `widened …` and `DISJOINT` over an item that declared nothing, on precisely the body shape `widen` exists to repair. The fence is now closed before the declaration is appended. **(ii)** `awk -v repl=…` applies **escape processing** to its value, so a token holding a backslash was PATCHed as something other than the string `die_on_invalid_paths` validated and `widen` echoed back: `src/a\tb` became a literal tab, which the reader's `tr` then split into two tokens. `repl` now reaches awk through the environment (`ENVIRON`), which does not escape.

  Grammar and the declaration rule stated in `SKILL.md` §1, both skill roots, and [`../docs/coordination/parallel-work.md`](../docs/coordination/parallel-work.md) §3, including the indent bound and the advice to quote in a **fence**, never bare. Fixture `tests/fsgg-coord/run.sh` grew a `#277` section (**26 assertions, 324 total**), pinning the three cases the issue named — a fenced line is not a declaration, a real-plus-quoted body takes the real one, an all-valid-token quotation reserves nothing (the fail-open asserted directly: `overlap` must never answer `DISJOINT`) — plus `~~~` fences, the 4-space bound and its ≤3-space complement, the bare-quote-above-the-declaration case that `head -1` would have under-reserved, all four halves of the `widen` writer (patch, append, collapse, close-the-fence), and `batch` passing a fenced-only candidate over with its reason. [`../.github/workflows/touch-set-drift.yml`](../.github/workflows/touch-set-drift.yml) needed no change: it shells out to `verify-paths` rather than carrying a second `Paths:` regex, so it inherits the fix — the drift surface #276 consolidated away. **Housekeeping:** #261 still declares another repo's files and must re-declare its touch-set before anything is scheduled against it. Re-digested client `4a20e239…` → `fefa8882…` and skill `a5a345e4…` → `5b4c1ca6…`. Propagates to `coordination-kit` receivers via the `coordination-coherence` gate.

- **2026-07-09** — Coordination-kit `fsgg-coord` + `intra-repo-parallel-work` sha256 bumped (@.github; #273, ADR-0021, ADR-0027): the **`Paths:` touch-set failed OPEN**. The skill documented the line as "comma- or space-separated **globs**"; `paths_from_body` strips a *trailing* `/**` or `/*` and nothing else, and `conflicts_between` compares tokens only by equality and subtree containment. There is no glob matcher anywhere on that path — so a leading `**/`, or any interior `*`, survived normalization as a literal path segment and matched **no file, ever**. And a token that matches nothing **conflicts with nothing**: `overlap` printed `DISJOINT`, `widen` reported it had cleared every in-flight claim, and `batch`/`take` handed two workers items whose real files overlapped completely. Observed on `FS.GG.Audio#4`, where `Paths: **/packages.lock.json` was simultaneously "disjoint from everything" and "covers none of the seven lockfiles it names" (`verify-paths --pr 5` → DRIFT). This is **ADR-0021's own defect one level down** — a lock that *succeeds* under exactly the conditions it exists to prevent — in the touch-set rather than the claim, and it is the same class as .github#257 (in-flight work invisible to the scheduler).

  **Fixed by failing closed, not by growing a glob engine.** An unmatchable token is now treated as an **unknown** touch-set — the state `paths_of` already refuses to schedule against when a body read fails — rather than as an empty one. `claim` refuses the lock (holding an item that reserves nothing makes your files invisible to every peer's overlap check); `widen` rejects **before** the PATCH, so the old, still-reserving declaration survives a rejected widen; `overlap` exits **2** (undeclared) and never prints `DISJOINT`; `batch` passes an unmatchable *candidate* over with its reason, and **refuses outright** when an item already *held* declares one, since that holder's real surface is unknowable; `verify-paths` gained a fourth verdict, `FSGG-PATHS INVALID`, because under a broken touch-set every changed file is trivially "outside" it. Items with **no** `Paths:` at all stay claimable and merely unschedulable, exactly as before — declaring nothing differs from claiming to have declared. Option (b) of #273 (implement the documented grammar) is deliberately **not** taken: a real pattern-vs-pattern overlap test is the hard half, and the fail-open hole closes without it.

  **Three fail-opens the guard itself nearly shipped**, caught in review, each now pinned by a test that fails without its fix. **(i)** `claim` validated via `die_on_invalid_paths "$(paths_of …)"` — but `paths_of` fails closed by calling `die`, and an `exit` inside `$( )` kills only the substitution subshell. A transient body-read failure therefore printed *"refusing to schedule against an unknown touch-set"* on stderr and then claimed the item anyway, exit 0. Assign first, then validate; `overlap` (`pa="$(paths_for_ref …)"`) already had this right. **(ii)** `widen` screened its **own** new tokens but not the in-flight claims it re-checks *against*, so a **legacy** holder declaring `**/…` still cleared it — the identical fail-open, surviving on the one command whose entire job is to shout about collisions. It now refuses to answer (exit 2) while still letting the re-declaration land, because widening is how a bad declaration gets **fixed**, including on a held item. **(iii)** [`../.github/workflows/touch-set-drift.yml`](../.github/workflows/touch-set-drift.yml) classified only DRIFT/OK/skip: `FSGG-PATHS INVALID` fell through to `else → skip`, which **deletes** the sticky comment and passes green, and the comment step would then have rendered it with the `✅ stays inside` branch. Fourth verdict added, matched *before* the fallback, with its own ⛔ comment.

  Grammar now stated honestly in `SKILL.md` §1, both skill roots, and [`../docs/coordination/parallel-work.md`](../docs/coordination/parallel-work.md) §3: exact paths and directory prefixes, trailing `/**` / `/*` only. Fixture `tests/fsgg-coord/run.sh` grew a `#273` section (**40 assertions, 298 total**); against the pre-fix client 15 of them fail, including "`#300` vs `#301` is NEVER reported DISJOINT", and each of the three review fixes above is likewise covered by an assertion that fails when its guard is removed. The unmatchable-token predicate lived in **four** hand-copied forms across two engines (one `grep -E` and three inline `jq` regexes); the jq copies are now a single `claims_with_unmatchable_paths` filter, since a later widening of one char class that the copies did not follow would silently reopen the fail-open on exactly the in-flight-claim guards that need it most. Consolidating surfaced that **two of those three guards had no test at all** (the `batch` assertion was reaching the per-candidate `grep` path instead) — 7 assertions now go red when the shared filter is neutered. Re-digested client `447a330c…` → `4a20e239…` and skill `79c54b3d…` → `a5a345e4…`. Propagates to `coordination-kit` receivers via the `coordination-coherence` gate.

- **2026-07-09** — **`schemaVersion` 1 → 2**: new top-level **`outside-fabric:`** opt-out list, and a gate that makes the roster's closed-world assumption checkable (owner github; refs #269, epic #266, ADR-0019). The roster is the list every org fabric iterates, so a repo absent from it receives nothing — no labels, no coordination kit, no audit — and *nothing could say so*: `coordination-sync --check --repo <full>` exits **0** for a repo that does not `receives: coordination-kit`, which is correct for a repo deliberately outside the fabric and catastrophic for one accidentally outside it. The two were indistinguishable to every gate we had, which is why `FS.GG.Audio` (the entry below) sat outside the roster for weeks while `repos-audit` — which only iterates repos *in* the roster — reported green. New [`../scripts/check-roster-closure.py`](../scripts/check-roster-closure.py) asserts closure from both directions: **(A)** every `dependencies.yml` `repos:` participant has a row here (offline, and the cheap invariant Audio violated), and **(B)** every repo live in the GitHub org (`GET /orgs/FS-GG/repos`) is either rostered or carries an explicit `outside-fabric:` row. Per epic #266's rule it **fails closed**: an errored, empty, or too-narrow org listing is an error, never a skip — in particular a listing that omits a repo we already roster proves the caller cannot see the whole org, so "not in the listing" cannot mean "does not exist". Exemptions are reviewed claims, not mute buttons: `reason` is required, a repo may not be both rostered and exempt, an exemption naming a repo that no longer exists fails as stale, and nothing is auto-exempt (archiving a repo must never be a way out of the gate). `outside-fabric:` ships **empty** — the org's seven live repos are all rostered. Wired into `coherence.yml` (every PR + push to `main`), fixture `tests/roster-closure/run.sh` (15 assertions); `scripts/repos.sh validate` grew the offline shape checks. Projection [`../docs/registry/repos.md`](../docs/registry/repos.md) updated in the same change.
