# Skill registry changelog

Reverse-chronological log of changes to [`skills.yml`](skills.yml) — the FS-GG org skill
registry (the authoritative catalog of process + product skills, ADR-0017). Its human projection
is [`../docs/registry/compatibility.md`](../docs/registry/compatibility.md) (§Versioned contracts →
`skill-registry`, §Coherence state → `skill-registry-published`).

**Protocol.** Mirrors [`CHANGELOG.md`](CHANGELOG.md) (the `dependencies.yml` log): every change to
`skills.yml` **prepends one dated entry** at the top of the Entries list below (newest first) and
sets the file's `updated:` date to match. Entries follow the same loose
`HEADER (owner; refs): body` grammar — name the skill id(s)/scope touched, the owner, and the
issue/ADR refs. `skills.yml` is **generated/reconciled from the producer skill-manifests**, so an
entry should say which producer manifest (and version/PR) a row was reconciled from.

`skills.yml` is a governed contract (`skill-registry`, ADR-0015): schema growth (a new field or a
tightened rule) is a tracked `contract-change` — bump `skills.yml` `schemaVersion` + the
`skill-registry.version` in `dependencies.yml` in the same PR that teaches `Fsgg.Registry`, and
advance the gate's `FS.GG.SDD.Cli` pin.

- **2026-07-10** — PREDICATE — `materializes-when` was never enforced; `fs-gg-testing` reconciled to Rendering's manifest (owner github; .github#292, epic .github#266, producer FS.GG.Rendering#90 closing the cross-repo request, grammar FS.GG.Rendering#77, ADR-0017/ADR-0022 §6): the gate emitted six finding kinds, and **every one is a predicate over a row's `sha256`/`source` or — since #289 — over its mere presence**. None compared the one field that is neither bytes nor presence: the **emission condition**. So a producer could widen or narrow a skill's `materializes-when` and this catalog silently kept the old one, with every digest green throughout. That matters more than a stale digest: `materializes-when` is what `scripts/skill-union-assert.sh --params` evaluates to decide whether a skill's **absence** from a scaffold is *legitimate* (ADR-0017's `[missing]`/`[unexpected]` classes), so a wrong predicate makes the union gate wrong **in a direction it cannot detect**. One row had diverged: **`fs-gg-testing`**, which this file called `profile == governed` while Rendering's manifest declared `profile in [app, headless-scene, governed, sample-pack, game]` — under `--profile app` the registry asserted the skill *should be absent* while the producer was emitting it. All other 35 rows agreed. **Which side was right (the question #289 deferred as "a cross-repo call"): the manifest.** The row was *faithful when written* — at the seeding reconcile (Feature 238, FS.GG.Rendering#76, commit `c550a75b`) the manifest really did say `(profile == "governed")`. Then **FS.GG.Rendering#90 — a `cross-repo:request` filed FROM this repo and accepted — deliberately widened it** (commit `f4abd68c`, 2026-07-04, *"widen fs-gg-testing materialization beyond governed"*), on the reasoning that the skill body is largely profile-agnostic and `game`/`app` authors were otherwise shipped a test surface and `FS.GG.UI.Testing` with no skill teaching either. No new owner's call was needed: Rendering's owner had already made it, on the record, and the registry simply never flipped — **stale for six days**. Reconciled to the manifest verbatim. **The gate:** a `predicate-matches` finding — for every row a producer manifest also declares, `materializes-when` must equal the manifest's (absent ⇒ `always`, ADR-0017), **failing closed**; `--write` now rewrites a diverged `materializes-when` in place exactly as it rewrites a stale `sha256`, touching nothing else on the row. Compared on a **whitespace-normalized** form (`profile in [a,b]` == `profile in [a, b]` — reformatting is not drift) but **never on grammar**: the C-style form Rendering shipped before **Rendering#77** (closed 2026-07-04, commit `cf93eabd`, which aligned the manifest on the ADR-0017 canonical grammar — both sides have emitted it since) is *semantically* identical and **still reported as a divergence**, because the ADR-0017 evaluator cannot parse it and reads such a predicate as **false**. Normalizing it away would make a producer's regression to an unevaluable predicate compare equal and report green — precisely the #266 fail-open shape, re-introduced inside the fix for it. (Rejecting non-canonical grammar *outright* is a separate tightening, .github#290.) A frozen mirror declares an id twice (ADR-0022 §6), so the row's `owner:` selects the authoritative manifest; two declarers that **contradict each other** are reported and `--write` refuses to pick a side rather than believing whichever repo sorts first. Manifests are now read **once** into a shared index feeding both `declared-completeness` and `predicate-matches`. No `schemaVersion` bump — no new field and no tightened *schema* rule; the strictness is in the **gate**, matching the 2026-07-08 and #289 precedents. No set/count change (36 rows: 16 process + 20 product), no `owner`/`source`/`sha256` change to any row. Projection [`docs/registry/compatibility.md`](../docs/registry/compatibility.md) needs no edit (it names counts, not per-row predicates, and the counts are unchanged). No coherence-state change: `skill-registry-published` stays as #289 left it. **Not fixed here** (separately owned, and red on `main` independently of this change): five rows re-staled by producer merges, the `fs-gg-audio` frozen-mirror divergence ([.github#295](https://github.com/FS-GG/.github/issues/295)), and `fs-gg-feedback-report` — declared by Rendering's manifest since `d481e72a` and still absent from this catalog, which is `declared-completeness` doing exactly its job.
