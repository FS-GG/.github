# Registry changelog

Reverse-chronological log of changes to [`dependencies.yml`](dependencies.yml) — the FS-GG
cross-repo contract & dependency registry. Its human projection is
[`../docs/registry/compatibility.md`](../docs/registry/compatibility.md).

**Protocol.** Every change to `dependencies.yml` **prepends one dated entry** at the top of
the Entries list below (newest first) and sets the file's `updated:` date to match. Entries
follow a loose `HEADER (owner; refs): body` grammar — name the contract/coherence id(s)
touched, the owner, and the issue/ADR refs. One entry per registry change keeps PR diffs
reviewable and avoids the merge conflicts the former single-line comment caused across the
org's parallel sessions.

This file replaces the ~42 KB single-line trailing comment that used to live on
`dependencies.yml`'s `updated:` field (freeze migrated verbatim below; see .github#129 /
review M4). The typed validator (`fsgg-sdd registry validate`) never saw that comment, so
no gate behaviour changes — this is purely how humans record the log.

- **2026-07-09** — **NEW COHERENCE ID `pin-feed-coherence` (coherent: true).** The repo's **embedded, Renovate-annotated version pins** are now gated against the **live org feed**, and the bump mechanism itself is gated (owner github; refs [.github#263](https://github.com/FS-GG/.github/issues/263), child of the fails-open epic [.github#266](https://github.com/FS-GG/.github/issues/266)). No contract version changed — this entry registers a **gate** and a **root-cause fix**, not a flip. Also annotates `cross-repo-auto-update` and `registry-validator-typed` with what this proves about them.

  **The hole.** `registry-feed-coherence` (the entry below) gates the registry's `package-version` rows against reality. Nothing gated the pins **the gates themselves run on**. `contract-coherence.yml` installs the typed registry validator at a pinned `FS.GG.SDD.Cli` version, and the row `registry-validator-typed` asserts `coherent: true` *on the strength of that pin tracking feed-newest* — because under the registry's additive tolerance a frozen typed validator silently degrades toward a "does the YAML parse" check. The pin froze at `0.2.1` while the org shipped `0.5.0` ([.github#127](https://github.com/FS-GG/.github/issues/127), "H2"), was advanced by hand, then froze **again** at `0.5.0` while the org shipped `0.6.0`, `0.7.0` and `0.8.0`. Found by eye during the `v0.9.0` release, three minors late, both times.

  **The root cause** — three hypotheses stood unverified in #263; this is the one that held. `.github`'s own `renovate.json` carried **no feed `hostRules` token**. `FS.GG.*` resolves only from the private org GitHub Packages feed, and Renovate does **not** substitute `{{ secrets }}` inside a preset pulled via `extends`, so the token must live in each repo's **own** config. All four product repos carry it. `.github` — which *authors* the preset and dogfoods it — never adopted its own requirement, on the recorded belief that "the `FS.GG.*` rules are inert here (no `FS.GG.*` PackageReferences)". An annotated **tool pin** is an `FS.GG.*` dependency too. Every `FS.GG.*` lookup therefore 401'd, no versions could be enumerated, and no bump PR could ever open. The symptom was recorded **twice** — *"only third-party Renovate PRs observed so far"*, in this registry and in the fabric guide — and read as a pending milestone rather than a fault; third-party packages resolve from `nuget.org` and need no token, so "PRs, but never for `FS.GG.*`" is precisely the signature of missing feed auth. The annotation manager's regex, the other leading hypothesis, matches the pin correctly (verified).

  **The gate.** `scripts/check-pin-coherence.py`, run by `.github/workflows/pin-coherence.yml` on every PR touching the pins/preset/gate/fixture, on push to `main`, and **daily on a schedule** — load-bearing for the same reason as its sibling: a CLI release that leaves the pin behind touches no file in this repo, which is exactly how three minors passed unseen. It asserts **both** halves of *"this pin can move, and it has moved"*: **freshness** (every annotated pin equals feed-newest, failing **behind** — the freeze — and **ahead** — a version no consumer can restore) and **mechanism** (this repo's Renovate config carries a `hostRules` token for `nuget.pkg.github.com`). Its **subject is the org preset's own annotation regex**, read from `default.json` rather than re-specified, so the gate and the bot cannot disagree about what a pin is: a reformat that blinds the manager also reds the gate.

  **Fails closed**, per the epic's rule. A missing/empty/wrong-host token, no Renovate config, a preset with no annotation manager, **zero pins matched repo-wide**, a pin named in `REQUIRED_PINS` gone invisible to that regex, an unresolvable datasource or non-`FS.GG.*` package, an unreadable feed, a 404, zero versions, or an unparsable literal is an **error**, never a skip. `REQUIRED_PINS` answers the case a scan structurally cannot: a gate that scans with the regex under suspicion sees exactly the nothing the bot sees, so the pins this repo is known to carry are named explicitly and a **disappearance** is red. Versions compare by NuGet **order**, never substring ([.github#268](https://github.com/FS-GG/.github/issues/268)). Feed reads and NuGet ordering are now shared with `check-feed-coherence.py` via `scripts/fsgg_feed.py`, so the two gates cannot drift into disagreeing about version order; `feed-coherence.yml` gained that path in its triggers. `tests/pin-coherence/` asserts each failure leg fires for its **stated reason** (the vacuous "must fail" defect the epic names, SDD#299), and is mutation-tested against 7 deliberate fails-open regressions — mechanism check never raises, freshness always OK, required-pin assert no-op, substring compare instead of order, zero-pins tripwire removed, a non-`FS.GG.*` package silently skipped, the `ignorePaths` guard disabled, Renovate's config-resolution order reversed — all caught.

  **Scanning exactly what the bot scans.** The gate skips the paths Renovate's `ignorePaths` excludes (`config:recommended` → `:ignoreModulesAndTests`: `**/tests/**`, `**/vendor/**`, …). Found the hard way: the preset's `managerFilePatterns` include `/\.sh$/`, so the gate's *own fixture* — whose heredocs carry annotation-shaped test pins — reddened its first live run over an `Expecto` pin Renovate would never have touched. A gate stricter than the bot is as wrong as one laxer than it. The converse is guarded by `REQUIRED_PINS`: an operative pin parked under an ignored path reads as *gone invisible to the manager*, which is red.

  **What it does and does not prove.** `registry-validator-typed`'s `coherent: true` is now **earned** rather than assumed. The pin is bot-managed again rather than a release-runbook chore — which is what #263's ask 2 proposed while the mechanism was unproven; enforcement at the point of use beats prose in a runbook. `cross-repo-auto-update` **stays `coherent: false`**: the missing token explains `.github`'s silence, not necessarily the product repos', and no green `FS.GG.*` Renovate sweep has been observed **anywhere**. Verified live at adoption: the one annotated pin (`FS.GG.SDD.Cli` `0.9.0`) equals the feed's newest, and `renovate.json` now carries the token.

- **2026-07-09** — **NEW COHERENCE ID `registry-feed-coherence` (coherent: true).** The registry's `package-version` is now gated against the **live org feed** (owner github; refs [.github#267](https://github.com/FS-GG/.github/issues/267), child of the fails-open epic [.github#266](https://github.com/FS-GG/.github/issues/266)).   **The hole.** `contract-coherence.yml` validated `dependencies.yml` against its **schema** and its **projection**. Nothing validated it against **reality**: the packages actually served by `nuget.pkg.github.com/FS-GG`. So publish-before-flip (FR-007) step 1 (publish) was gated hard and step 2 (flip) was gated by *nobody noticing*. This was named as the root cause in the [.github#250](https://github.com/FS-GG/.github/issues/250) entry below — *"no gate compares the registry's `package-version` against the live feed"* — and then recurred twice: the `fs-gg-ui-template` `0.4.0-preview.1` flip that was never made at all (reconciled in the entry above), and the frozen validator pin ([.github#263](https://github.com/FS-GG/.github/issues/263)). Every instance drifted in the **safe** direction (feed ahead of registry), which is luck, not design.

  **The gate.** `scripts/check-feed-coherence.py`, run by `.github/workflows/feed-coherence.yml` on every PR touching the registry, on push to `main`, and **daily on a schedule**.
