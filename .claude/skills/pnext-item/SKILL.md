# Complete the selected Delivery

One accountable owner carries implementation, verification, repair, review and permitted delivery through
acceptance. Under [work-board](../work-board/SKILL.md), read the native issue's complete Done when and owning plan,
including publication, installed, participant and recovery obligations. Follow the common **Normal execution**
section of the [lifecycle contract](../work-board/references/lifecycle-contract.md). Ordinary isolated checks
need no Root runtime approval; covered successful steps need no repeated phase approval. Changed scope,
authority, uncertain effects or exhausted bounds return for reconciliation.

Use the routine route by default. Only recorded explicit human instruction selects the
[heavyweight protocol](references/strict-item-lifecycle.md) for named scope. Protected effects retain their
substantive safeguards within either route. A refusal blocks its affected action; it never authorizes
weakening a gate or switching ceremony.

## Routine delivery

1. Recover the existing accountable owner, native Delivery, worktree and PR/head. Adopt exactly one
   unambiguous open routine PR; repair on the same branch and PR. Multiple candidate PRs refuse admission.
   Fresh work starts from the current default branch on `routine/<item-slug>`. A board projection's lag
   cannot justify another assignment. The coordinator retains intake and Status decisions; workers
   supply evidence rather than creating claims, identities, ledgers or mandatory return packets.
2. Implement the admitted promise in the isolated worktree, within the stated resource share. Run
   proportionate checks, the [owner self-check](#owner-self-check-before-review) and the same touched-path
   gates as CI before requesting independent review. Preserve first failures; after repeated same-class
   failures inspect relevant callers, failure and cleanup paths before coherent repair. Split independent
   concerns into separately reviewable PRs under the existing one-chain/two-managed-PR limits; retain one
   continuous PR for the current slice.
3. Keep the PR draft until required gates pass; name inherited main failures. Use the canonical creation
   and delivery helpers from the [exact-source route](../work-board/references/lifecycle-contract.md#qualify-the-actual-path-and-deliver-exact-source).
   A moved head needs fresh review and binding. The body has exactly one
   `<!-- fsgg:routine-development/v1 head=<exact-head-sha> operation=<allowed-operation> -->` and exactly one
   `<!-- fsgg:delivery-continues/v1 -->` or `<!-- fsgg:delivery-completes/v1 -->`.
   Use continues whenever PR work, publication, installation or readback remains; completes means nothing
   in the full Done when remains after merge. `Refs` the Delivery without closing keywords. Other native
   closing links require that issue's complete fulfilled promise. For fixtures/release controls, name the
   injected clock, observed source or isolated sandbox in the body under the linked fixture rule.
4. Obtain one independent exact-candidate source review for code/governing changes, repair substantiated
   defects and re-run reviewer probes. Inert prose uses owner review and cheap checks. Preserve exact-head
   required CI, ADR-0084 coherent validation, native merge gates and actual tested-checkout identity. A
   reviewer recounts headline counts from outputs; untraceable claims remain Unknown. Applicable publication,
   installation and runtime effects continue through their qualified routes with independent readback.
5. Record accepted scope/date/evidence and remaining assertions in the existing owning issue. Quote
   generator-printed counts; close only its fulfilled promise through authorized native closure and Status
   readback. Preserve partial effects without replay. Do not automatically close parents. An external hold
   names its supplier, missing result and reopening condition. Return evidence or held remainder to work-board,
   which reconsiders intake and continues clearing. A direct single-item invocation ends at that boundary.

The routine route adds no lifecycle ledger, receipt family, review actor or projection PR. Do not execute
heavyweight identity/claim/critique/done-stamp steps without explicit selection. Telemetry and Observation
projection stay advisory; mandatory native reconciliation and effect safeguards remain.

## Owner self-check before review

Before requesting review of a governing or code change, probe the actual failure boundaries. This is
owner work, not another critic or report; inert prose needs none of it.

- **Range:** fuzz or property-test across the full range the API accepts, not only typical values.
- **Partial failure:** for each multi-step write or effect, ask what happens on failure or kill between steps, and test it.
- **Planted bugs:** disable each safety check or guard in turn and confirm a test fails.
- **Reviewer probes:** when repairing after review, re-run all of the reviewer's probes on the new head and add their classes to your tests.
- **Cross-cutting defects** (sizing, concurrency, lifecycle): write the invariant first, then the code, not point fixes.
