# drive-board (FS-GG)

The existing programme integrator allocates independent current slices across repositories; the
owning issue/plan and native delivery evidence retain authority. The board supplies planning and
visibility, not an execution ledger or a second scheduler.

## Prepare the successor without activating it

Read the [organization inspection contract](../check-board/references/organization-v2-inspection.md)
and [organization scope](references/org-scope.md). This edition prepares .9/.11 consumers only.
Exact installed qualification, admitted final binding/schema/membership/view readback, UI and real-use
comparison remain required before the coordinated consumer switch. Historical three-active and
no-dispatch acceptances are not organization-v4 permission. No worker dispatch or live write follows
from preparing or reading this skill. Current authorized owners continue from issue/plan/native PRs.

After accepted cutover, consume exact binding-v4/inspection2 and the integrator's one-invocation
stdin/native joins. Select the explicit ordered capacity-safe subset per slice, retaining selected
and deferred reasons. Reconcile every membership and non-enrolled in-flight/reserved conflict; a
view filter never enrolls work. Human Status stays planning input. Missing global facts hold new
board-derived selection; scoped gaps withhold only conclusions they affect. Never fall back to V1.

## Keep one owner through native closure

Routine is default. Only recorded explicit human instruction selects heavyweight process for named
scope; paths, operations, labels and inherited strict state are not process selectors. Preserve
substantive checks and effect safeguards independently; a technical refusal does not change the route.

Continue an existing unambiguous owner and PR/head before assigning source implementation. Missing or
conflicting ownership is a decision/gap, not permission to duplicate work. Assign one accountable
routine owner in an isolated worktree with an explicit current touch-set. Preserve outcome identity,
independent slice/attempt identity, action/prerequisites, scope, authority, acceptance and original holds.
Authorized source changes need no manufactured issue, claim, packet, driver-event ledger or phase row.
Use [work-programme](../work-programme/SKILL.md) for programme ownership and source/effect boundaries.

The owner implements, repairs, obtains one independent source review where required, and carries the
same PR through relevant tests, required CI and native readback under existing admission. Agent review
can provide independence from authorship; no mandatory critic/confirmation chain or fixed waves are
introduced. Human-selected heavyweight work retains its own explicit governing route; this organization
queue does not restore V1 claims, Class/Phase/severity rank, done-stamps or scheduling ledgers.

Before actual execution, recheck the native/runtime/action/prerequisite/intake/resource/reservation facts
that determine the selected operation. Native issue-author permission is separate from parent operation
authority. Account chosen demand before admitting another slice; free worker slots do not establish
review/hosted-CI capacity. Preserve uncertain/expired holds until their real release condition is observed.
Use [host-loop](references/host-loop.md) and [backlog triage](references/backlog-triage.md) for this scope.

## Bind the requested model and observe the original work

For normal-cost dispatch use [drive-board-normal](../drive-board-normal/SKILL.md); for explicit best
quality use [drive-board-best](../drive-board-best/SKILL.md). Bind the actual supported model/effort,
never a host default or silent substitution. Product work-board routes are separate. Prepared routing
is not installed adoption or permission to launch a worker.

The designated integrator uses the existing PR admission/delivery route, exact-head required checks
and ADR-0084 coherent validation. Classify first, start coherent validation, and permit valid exact-head
reuse only for its qualified facts. Pending and disputed validation remain visible; disputed work blocks
dependent acceptance or activation. It does not trigger a heavier process. Keep at most two managed
PRs per repository and one active PR per
coherent chain; source preparation continues independently when the hosted queue is full. Retain first
failures and unknown effects. Source merge, publication, installed use and native acceptance are distinct.
Report deliverables, changed blockers, needed decisions and changed promised checkpoints from existing
native results; unchanged ticks require no comments, projection or reporting-only workload.

Stop new assignment when no currently authorized action is eligible within actual capacity; identify
blocked/unknown/deferred slices and the supplying owner/deadline instead of asserting the board is
finished. A merged slice narrows remaining work and does not auto-set the outcome Done. Recovery keeps
owners, existing PRs and original effects; [deep detail](references/deep-detail.md) retains historical
mechanics without granting organization V1 authority.
