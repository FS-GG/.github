# Delegated bootstrap and restart

Read this when assigned bounded recovery or packet assembly. The parent supplies user scope, known
campaign/attempt identities, available references and actual capacity/operation constraints. Read the
parent skill and applicable governing instructions in full; do not inherit the parent's conversation.
Use the implementation route selected by the skill. Bootstrap is recovery, not feature planning.

## Recover the selected window

Read the existing private dispatch index first if available. It is a navigation cache, never authority.
Resolve its source references and fresh-read the affected native facts. Use the latest handoff to fill
missing references, then relevant [protected v3 open outcomes](../../../../docs/roadmaps/2026-10-07-unified-development-roadmap-v3.md#2-open-work-and-owning-plans) and owning plans. Avoid reading the
entire handoff or roadmap merely to select a known lane. Preserve prior delivered work and historical
failed/unknown attempts; never infer completion from their summaries or recreate absent receipts.

If the session was killed before saving a handoff, or the latest report predates the interrupted work,
use [crash recovery](crash-recovery.md). A missing index, packet or temporary artifact does not prevent
recovery from the protected plans, surviving Git work and native authorities. Establish a complete
reservation view and reconcile unknown effects before marking affected lanes ready.

Retain the complete active-reservation population, including unreadable owners and pending operations,
even when only a subset is ready. Distinguish original/current items and attempts, source/publication/
installed/native/projection boundaries, exact source and PR heads, touch-sets and prerequisites. Unknown
reservations continue to occupy their declared resources. A changed owner or missing return requires
reconciliation by the parent, not reassignment by this worker.

For explicitly selected organization V2 inspection, read the existing
[organization contract](../../check-board/references/organization-v2-inspection.md) and preserve its
population, executable and consumer admission. An assigned lane does not require a full board census;
the retired skill name supplies no native acceptance.

Read [adapter](adapter.md) and assemble the existing `fsgg.programme.snapshot/1`. Use `frontier` for
initial recovery and `delta` with explicit evaluation time and policy/evaluator/user-scope identities
when a genuine base exists. Retain whole helper results privately. Missing bases resynchronize; copying
facts does not renew source timestamps. The snapshot and helper output remain advisory.

Bootstrap permits source/native reads and private recovery artifacts. It does not permit implementation,
dispatch, branch/worktree changes, PR creation, merge, publication, service activation or operation retries.
Propose any required isolated worktree for the parent to admit. Do not add a permanent service or another
coordinator. Prefer already fresh owner artifacts to repeating their investigation.

## Assemble packets outside parent context

Prepare packets only for selected ready lanes. Resolve applicable instructions and include their complete
files as mandatory instruction references; stream them through the existing packet helper instead of
printing their contents to the parent. Keep source, logs and observations marked as data. Include the
exact installed work-roadmap path, owner plan, bounded window, identities, authority, acceptance and stop.
For new/material feature planning, also use [feature planning](feature-planning.md).

The receiving owner checks instruction applicability and missing obligations before acting. A successful
packet build proves correspondence to declared inputs, not universal instruction discovery. Preserve
omissions and refusals; do not shorten governing instructions to make a packet fit. The parent receives
packet path/digest, scope, instruction inventory and omissions, not the body. Root-owned decisions or
safeguards still require the parent to read their applicable instructions and necessary exact evidence.

## Return a decision view

Return paths/digests for the snapshot, helper results and prepared packets, then a compact view containing:

- Campaign and original/current identities, source revisions and actual observation coverage.
- Every active reservation: owner, repository, exact head/PR or operation reference, touch-set and state.
- Ready lanes and their prerequisites, actual local capacity and hosted queue observations.
- Concrete parent decisions, conflicts and unknown effects, with exact evidence references.

Aim for at most1000 words for bootstrap. Reduce repeated prose and history first. If the complete active
inventory or material constraints exceed that target, expose the size and provide bounded retrievable
sections; the parent must consume the complete reservation inventory before scheduling affected work.
The target never permits dropping obligations, reservations or unknowns. Worker interpretation cannot
admit a native effect; the parent rechecks the relevant authority at its existing admission boundary.

## Keep restart navigation small

Maintain `dispatch-index.md` alongside the existing private snapshot and evidence, with paths/digests
to current scope/instructions, snapshot/delta base, owner returns and packets. Include stable owner and
attempt identities, exact heads, complete active reservations, dependency boundaries, pending original
operations and unresolved parent decisions. Link the detailed handoff and qualification artifacts.
Keep timestamps tied to actual reads. This is a disposable navigation projection, not a new schema,
ledger or source of completion authority; losing it must not release a reservation or restart an effect.

Update the index after material changes and at an authorized handoff, not every CI tick. Future recovery
starts from these pointers and verifies native state. Preserve historical detail outside the restart
message rather than copying it into a larger session summary. Do not claim control over automatic
runtime compaction or availability of token counters.

Measure parent startup/read bytes, bytes per normal return and evidence expansions when observable,
separately from helper IO and total worker usage. Charge bootstrap, packet assembly and repairs to their
existing lineage. A smaller parent or a static entrypoint reduction does not establish total savings.
