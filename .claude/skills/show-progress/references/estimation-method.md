# Estimates only when they help

The default progress report needs meaningful milestones and obstacles, not numerical scoring.
Use this guidance only when a forecast or number helps a decision or the user requests it.

- Start from concrete remaining work and comparable completed work. State the main assumption
  and give a rough range; separate active work from waiting.
- Compare against a previous estimate only when scope and units match. Otherwise call it a
  first estimate or explain the scope change. Never invent a baseline.
- A dependency with no resolution date prevents a reliable calendar forecast. Give the next
  milestone or a conditional duration after it clears, if supported.
- Use completion percentages only with a meaningful denominator. Do not infer them from PR
  counts or convert them into an ETA. Avoid programme-wide percentages across unlike lanes.
- Missing measurements mean unknown, not zero. Mention the material gap once; do not fill
  the report with repeated unknown fields.
- Count shared dependencies once. More agents do not imply proportionally faster delivery.

Keep the explanation beside the number and brief. Formal forecasting methods and their
limitations are background in [research.md](research.md), not required reading for an overview.
