# Selected NuGet release entrypoint

Read [publishing-and-deployment](../publishing-and-deployment/SKILL.md) before acting.
It owns the current release route, coherent-set versioning, candidate/preflight,
feed verification, promotion and selected consumer adoption. This compatibility
name supplies no additional release, retry or recovery authority.

Resolve the actual producer, changed package inputs, promoted predecessor and genuinely
owed release. Source delivery, candidate qualification, publication and installed
adoption remain separate. Do not release every producer merely because this entrypoint
was invoked; preserve existing publication owners and exact selected operation scope.

For the hub coherent set, use the selected successor operating window in
[utel-release-successor](../../../docs/roadmaps/utel-release-successor.md).
Require its immutable candidate/run/artifact/raw archive and successful `publish=false`
preflight before a separately admitted publication. Preserve the original bytes,
journal and independent readbacks; a consumed publication or unresolved send never
becomes a new operation by changing an identifier or rerunning a workflow.

Historical release-saga prepare, component-publisher and promote routes remain sealed
under GS2-08.9. This skill provides no executable legacy recipe or fallback. Missing
current authority, tooling or feed evidence leaves the affected operation incomplete.

Use scoped normal PR delivery for source changes. The global managed `speckit-merge`
recipe is excluded from FS-GG landing: no branch sweep, direct trunk push/deletion,
mandatory repack or shared-cache purge. Retain canonical publication and consumer
owners; do not patch a vendored global skill to repair repository routing.

Report the actual selected source/candidate, operation result and remaining acceptance.
A package, tag, registry digest or green source PR alone does not complete adoption.
