# Host Loop

Apply the canonical [work-board](../SKILL.md) scope, owner, capacity and delivery rules.
This reference provides no alternate scheduler, fixed waves, claim/status write, critic chain,
feedback ledger or projection requirement. Selected V2 inspection and independent native/effect
admission remain mandatory. Missing facts stay Unknown and retain affected holds.

Historical V1 mechanics remain in immutable Git history, not an executable fallback.

## One primary progress record

Keep the current source identity, accepted scope, blocker, accountable owner and next action in the
existing primary owning issue. Dependent issues retain their own complete Done when, acceptance,
Status and dependency, but link to that record for changing prerequisite details. Update them when
their own assertion or dependency changes, rather than copying every source hash, CI result and
checkpoint into each parent and consumer. Preserve prior outcomes and evidence through durable
owning comments and references; a compact current view does not erase history.

## Bounded delegation and runtime observation

Root reviews one concrete finite envelope using [delivery reliability](delivery-reliability.md#finite-delegated-sequence-and-isolation)
and [ADR-0096](https://github.com/FS-GG/.github/blob/main/docs/adr/0096-proportionate-verification-and-unrecoverable-holds.md#decision).
The owner advances its ordered steps on verified success without repeated approvals, retaining each
original clock, substantive review/required CI and independent readback. Stop on first failure,
Unknown, determining drift or budget exhaustion; no automatic retry or replacement identity.
Review the complete known conditional sequence once, including collection and retirement, rather
than requiring success-by-success coordinator approvals. Standing authorization for ordinary isolated
verification and bounded read-only Home diagnostics remains in force. A changed envelope needs its
concrete admission reconciled under existing authority, not an automatic new user-permission round trip.

Use typed running, paused, stopped and reported-but-unverifiable observations with actual
boot/namespace/source/clock and authentic birth scope. Unknown birth cannot authenticate a witness.
Cleared current manager metadata does not clear an original failed or uncertain outcome. Preserve
old shared-store objects and scoped holds; prove isolation before excluding their interference.

Keep runner → genuine bake → registration → first consumer primary. Delegate bounded source work
only to remove a concrete dependency, retaining its owner through applicable publication/adoption.
Prepare reusable builder and selected desktop/Orca/IME facilities after the first completed runner
run; source-bound handoff across different runtimes grants no native qualification. Report changes,
first failure/Unknown or envelope completion through existing custody, without unchanged approval loops.
Exercise producer → observer custody → worker launch → collection → retirement as the smallest
complete runtime path before adding full export or bake members. Source constructors and passing
artifact checks cannot establish callback completion or native cleanup.

## Own process findings and disposition

Executing agents report material process problems through existing owning issues/PRs and worker returns,
using the [findings route](https://github.com/FS-GG/.github/blob/main/.agents/skills/pnext-item/references/findings-and-filing.md).
The root integrator ensures every material report receives a reasoned disposition: repair within current
scope, attach to existing work, route a distinct improvement through canonical intake, investigate, defer
or decline. Preserve independent reviewers' disposition rights. Unresolved findings retain an accountable
owner, next action and reconsideration condition in existing native context. Semantic deduplication
precedes new filing; disposition never automatically creates an issue or selects implementation.

For an accepted improvement, define proportionate verification of its intended effect. Capture reusable
verified lessons through Atlas, or retain the capture gap and owner. Verify source delivery separately
from applicable publication/installed instruction adoption before claiming active use. Reporting and
disposition grant no dispatch, reservation release, uncertain-effect retry, Status write, weaker acceptance
or closure authority. Do not introduce a separate reporting worker, mandatory packet, duplicate ledger,
measurement campaign or recurring unchanged reports.

**Keep an owner for reported finding packets.** Canonical work-board owns coordination.
When an existing owner reports an evidence-backed distinct finding or a known `fsgg:finding-packet`
needs disposition, retain that finding and its source identity in the existing owning issue/native
thread. Resolve its accountable owner before treating it as new work. If a separately authorized
`board-analyst` is available and useful, send only the bounded relevant finding for adjudication;
its verdict never dispatches, claims, merges or grants operation authority. Otherwise the current
owner applies the existing evidence/materiality and deduplication boundary. Do not strand a known
finding with no owner, scan all comments on every cycle, create duplicate issues or launch a worker
merely to fill capacity. Missing analyst availability is not a source-delivery gate. The current owner may dispose and file directly through [canonical intake](intake.md);
analyst availability never requires a packet or second filing actor. Old wave/slot assumptions do not
apply to this coordinator.
