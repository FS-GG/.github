The canonical [work-board](../SKILL.md) governs current behavior. Historical pilot/default,
packet/return/index and reporting-cadence instructions below describe retained diagnostic contracts
only: they are optional and cannot restore roadmap scheduling, duplicate current-status/closure
upkeep or an active legacy workflow. Current scope and source/effect admission take precedence.

Read this reference when planning the next horizon, diagnosing recurring qualification failures or

reference does not start development, add gates or authorize protected effects.

## Final inputs and failure-gated invocation

This section governs original-operation effects. Ordinary development verification under
[ADR-0096](https://github.com/FS-GG/.github/blob/main/docs/adr/0096-proportionate-verification-and-unrecoverable-holds.md)
(local build/test/static check of unpublished source in a fresh isolated root, with no credentials,
shared/remote writes or publication/live-store/Home/VM/native-capability effect) is exempt.

Use the same exact typed values to derive admission, reservation and the operation request: stable
`sliceId`, attempt, operation, accountable owner, exact PR/head and actual paths/touch-set, plus the
selected binding/native joins. Reuse the existing owner/attempt and custody; independently assembled
lookalike identifiers cannot prove self-exemption or absence of overlap. Preserve every relevant known/
Unknown hold until its original release condition is independently observed. A completed-source path
handoff transfers only the explicitly verified subset; it does not release the whole row, other paths,
runtime/effect custody or Unknowns. No new packet or ledger is required.

Read [capacity/context](context.md#capacity-window-and-assembled-test-candidate) for supported
operation-specific fits and their current observations. Select the actual transitive execution graph,
including Python/shell forwarding ports, build servers and cleanup. Preserve exclusive/large-image
profiles while admitting useful independent operations that fit; entry language and free worker slots
establish no resource profile. Check actual producer framing, including valid trailing newlines;
distinguish original-resource from encoded compression integrity and exercise the declared cache graph.
Preserve the intended execution/input seam; a mock success cannot replace it.

Reserve the full operation horizon through original terminal, artifact retention and scoped cleanup.
Inspect final guards as well as launch steps: a candidate that checks protected `main` again before
retaining an artifact needs that ref stable until that check, even when an intervening merge edits only
documentation. File-disjoint source is insufficient to prove ref/output disjointness. Name the affected
ref/write domain and existing owner for this finite horizon; do not freeze unrelated domains. When a
selected guard compares a broader snapshot, account for its actual covered writers too. A refused
Prepare without retained diagnostic detail does not establish which writer or input caused refusal.

Freeze the final handoff input bytes and hashes before the final preflight. Validate the actual final
inputs, schema/branches, typed identity joins, content hashes, source/head/paths and remaining capacity
in one failure-gated sequence with invocation. Create owner-private final inputs exclusively at mode
`0600`; re-read their exact bytes/hash and refuse a preexisting file or weaker mode. For typed capacity,
reservation and action observations, require all three nonempty evidence arrays with actual supplier/
time attribution, and true accepted prerequisites plus the complete flag. Dating an empty template or
copying pending supplier text does not finalize those facts. Refresh actual native/body/owning-plan and
protected-base joins; unchanged content blobs do not make an old revision join current.
Every check must succeed before invoking the selected route; a failed check must prevent later shell lines as well as the constructor/launch. Use explicit
success chaining or a controller that stops on any failed prerequisite. A changed input/hash invalidates
the checked candidate: reconcile it and preflight the final bytes again within existing authority.
Start the finite original clock before setup/helpers and include their actual cleanup and final retention;
clip child work to leave that reserve. A new wrapper or per-checkpoint packet is not a substitute for
completing the existing maintained route's preconditions. At dispatch/push, reconcile a stale event base
on the same owner/branch/PR and obtain the required current-head CI; never relabel an old event as fresh.

Retain original refusals, partial effects and uncertain outcomes with their operation identity. Diagnose
and reconcile the original before any separately admitted continuation; never blindly retry or mint a
replacement identity. Describe these checks as finite cooperative verification at the observed boundary,
not an atomic transaction or server-side compare-and-swap guarantee. They grant no native effect,
settlement, reservation release or acceptance beyond the selected qualified route.

## Finite delegated sequence and isolation

Apply [ADR-0096 section C](https://github.com/FS-GG/.github/blob/main/docs/adr/0096-proportionate-verification-and-unrecoverable-holds.md#decision)
for one Root-reviewed finite sequence of protected effects. Bind exact source/inputs, credential and
runtime context, ordered actions, resources, write/output domains and each step's original identity,
clock, success and independent readback. Advance only on verified success; no repeated approval is
needed within that envelope. Closed outputs may feed only reviewed, checked derivations. Otherwise
end before the unknown input. Stop on first failure, Unknown, determining drift or exhausted bound;
retain the original without automatic retry, clock renewal or new-ID replay.

Prove engine graphroot/storage, runroot/runtime, temporary/output and actual process isolation,
including image import/acquisition, backing, engine database, rootless helpers and cleanup. Preserve
old holds and Unknowns; block only relevant interference. Exercise actual canonical credential/policy,
workflow/trigger/inventory and runtime preflight early. Keep typed runtime observations and original
outcomes separate from cleared manager metadata, as described in [host guidance](host-loop.md#bounded-delegation-and-runtime-observation).
Ordinary isolated tests and authorized read-only diagnostics acquire no new gate from this section.

## Reuse an accepted evidence baseline

Identify an accepted source/evidence bundle once by its immutable identity, verified artifact hashes,
acceptance scope and durable review reference. For a successor, review changed files and affected
dependencies against that baseline, reusing unchanged verified bytes. Refresh determining native
head, policy, workflow, credential and runtime facts when their source or capability changes. Historical
byte verification does not prove that a current mutable path still contains those bytes.

Retain original run identities, limits, failures and Unknowns when adding later observations. Keep
artifact integrity, source review, publication, process/writer/namespace settlement and consumer
acceptance distinct. A changed source inherits neither an earlier test result nor earlier native
acceptance. Required exact-head CI and coherent validation retain their existing rules.

The optional `scripts/evidence-manifest.py verify-delta` helper provides a compact machine-readable
view of source identities, original outcomes, artifact hashes, reported acceptance scope and unresolved
gaps. Select its baseline and receipt by explicit hashes. Its short report distinguishes historical
proof reuse from current payload reads; neither a manifest nor a receipt creates acceptance or execution
authority. Keep private evidence in its existing custody, without introducing a mandatory packet or
second lifecycle ledger. Use the existing primary issue for progress, as described in
[host guidance](host-loop.md#one-primary-progress-record).

## Priorities and observation

Apply these defaults through the maintained workflow and optional evidence/observation helpers;
they require no new service, mandatory receipt ledger or rollout programme:

1. Make first failures sufficient to diagnose; independently retain cleanup and reporting outcomes.
2. Exercise actual execution seams and final inputs before expensive qualification.
3. Move deterministic metadata/schema/launch-closure preflight ahead of costly stages.
4. Improve CI setup/build reuse and scheduling within ADR-0084 and proven capacity; do not drop checks.
5. Finish selected installed consumer slices and apply compatible cohorts rather than expanding near-finished work.
6. Record precise external suppliers, missing evidence and reopening conditions; repeat discovery only on new information.
7. Keep navigation compact and reuse verified immutable evidence while refreshing live authority.

The open index should state current acceptance, the next assertion, blocker and owning link. At review,
the FABLE reference row contained roughly 1,440 whitespace-separated words of history. Preserve that
history in owning reports rather than repeatedly loading it as current scheduling state. Do not retain
a completed exact-store migration as unfinished merely because a broader operational row remains open.

Measure first-pass qualification, terminal diagnostic completeness, time to accepted installed behavior,
actionable-result-to-closure latency and repeated evidence exposure from existing necessary operations.
Where available, count coordinator interventions per original run, repeated evidence reads and time
from source readiness to the first genuine native execution. Distinguish locally measured verifier
reads/reuse from reported operation observations. Missing coverage stays Unknown; token savings remain
unmeasured without attributed usage. Do not add a measurement workload or gate to obtain these figures.
Record repair causes and the original item population, including failed/stopped attempts; distinguish
useful verification from harness repair, external waiting and coordination. Use PR/check timings as
supporting metrics, not accepted-feature counts or whole-family cost. State denominators, freshness,
coverage and unattributed intervals. Do not start workloads solely for measurement or claim a speedup
from guidance edits, shorter helper output or an increased timeout.
