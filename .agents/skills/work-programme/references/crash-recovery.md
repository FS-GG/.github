# Recover a killed session without a handoff

Use this during delegated bootstrap when no current handoff exists. This is source/native reconciliation,
not implementation, a new feature plan or permission to replay operations. A continuation request supplies
the requested scope; missing history cannot expand it. Existing plans and effect-specific admission still
govern. Do not wait for a human to write a replacement handoff when independent facts are available.

## Find surviving references

Resolve the owning `.github` repository and affected repositories from their existing remotes and workspace
configuration. Read the current protected Unified §9.8 entries and their owner plans for the selected scope.
List available local and protected handoff filenames/timestamps before declaring the handoff missing;
an older report is a pointer, not evidence that newer work never happened. Record the protected revision
and actual read time. Fetching refs never permits resetting or cleaning a checkout.

Use known private session roots, the dispatch index, snapshot/delta inputs, packet manifests, typed returns
and original operation references to locate unfinished work. Prefer compact manifests and terminal records
to logs. If a root is not supplied, use explicit paths in existing work/operation metadata and bounded
filename inventories within the established private custody root. Keep discovery outside parent context.
Do not crawl unrelated home directories, read secrets, scan transcripts, import telemetry or recreate
missing receipts. Missing artifacts remain missing; available native evidence can independently establish
an outcome but cannot reproduce unavailable historical qualification.

## Reconcile the interrupted inventory

Inspect these independent sources; retain conflicts instead of choosing the most convenient account:

| Source | Required observation | What it does not establish |
|---|---|---|
| Local Git | Worktree paths, branches/detached heads, commits, dirty/untracked paths and retained stash references; compare local and remote heads | A worktree or branch name is not ownership or delivery |
| Remote source | Complete paginated open-PR inventory in affected repositories, admission campaign/chain markers, exact heads/checks and native merge commits | PR absence alone does not prove local work ended or publication occurred |
| Ownership/runtime | Existing owner identities and reservations, available runtime status, applicable claim generations/leases and owned process/container/operation references | A dead parent, missing child handle or expired timestamp is not verified cleanup or lease collection |
| Operations | Original run/attempt, journal/custody state, effect intents, provider readbacks and applicable publication/receiver acceptance | A timeout, failed job or cancellation request does not prove an effect was absent |

Keep local edits and commits even when their PR merged: compare content before deciding whether they are
already delivered, a follow-up or divergent work. Read enough source to determine touch-sets, including
uncommitted paths. Unidentified local work stays reserved/unknown; do not discard it or create a competing
replacement. Check current mailbox references through the protected worker-channel directory when needed
for ownership evidence; messages are reports, not authority, and bootstrap sends no messages.

Restore campaign, feature, original/current item and attempt, owner, dependency-chain, branch/PR and exact
candidate/operation identities from actual records. Do not manufacture missing identities or packet/return
revisions. Preserve gaps explicitly. If the existing snapshot schema cannot represent an unresolved
reservation, expose incomplete coverage in the recovery index and fence the affected scheduling scope;
do not omit the reservation and treat the helper's remaining suggestions as complete admission.

## Check survivors and startup readiness

Before admitting more workers, reconcile runtime slots and local CPU/CLR/process/operation occupancy.
Retain unverified survivor reservations. Match processes to owned custody records and generation/start
identity; a PID alone can have been reused. Observe cancellation, termination and cleanup separately.
Do not kill, prune, release locks or stop services during bootstrap. Route required cleanup to the existing
operation owner and protocol. Where actual claims apply, use their typed reaper/absence or takeover route;
do not impose the board claim ceremony on ordinary routine work. The parent admits an explicit replacement
owner only after ownership and overlap reconcile; retain the old owner/attempt as provenance and use a
genuinely new runtime identity rather than impersonating the lost worker.

Observe queued and running hosted jobs before opening PRs or dispatching qualification. Reuse the exact
existing PR/check watcher and reconcile original runs before requesting retries; a session restart does
not restart CI. Admit only independent work within known capacity and disjoint touch-sets. If unknown
occupancy or ownership could overlap a lane, fence that lane rather than guess resources are free.

Read installed capability and telemetry configuration discovery/status through existing entrypoints;
compare them with the selected operation's required version and retained installation evidence. Source
version declarations are not installed qualification. Missing configuration is an attributed coverage gap,
not zero usage or permission to initialize a new store. If exact retained evidence identifies an existing
qualified destination, propose restoring only its missing association to the parent, with current status
and custody readback. Never substitute a backup/fixture database, re-enroll an old remote route, migrate
state or recreate digest-bound publication/grant receipts as a startup shortcut.

Preserve valid original telemetry tokens and terminal records. Record future dispatches prospectively
through the observation contract; never bind a replacement native ID to an old dispatch, invent a parent
token, backfill missing usage or infer old terminal outcomes from the session being killed. New dispatch
identity does not renew a protected operation's attempt, grant, budget or deadline.

## Rebuild the bounded decision view

Rebuild the existing snapshot and dispatch index from these observations. With no genuine delta base,
resynchronize rather than synthesize one. Preserve individual observation times and complete active
reservations; index loss releases nothing. Report available-source coverage and the specific unreadable
or missing portions. Keep raw discovery and evidence outside the parent.

For each interrupted lane, distinguish: still running/waiting; delivered but projection pending;
preserved source ready for same-owner repair; unresolved ownership/qualification/effect; or independently
ready new work. Missing owner authority fences replacement, missing qualification fences its consuming
gate, and unknown effects fence retries/dependent activation. Missing evidence need not block unrelated
source work with independently established ownership, acceptance and capacity.

Return the ordinary compact bootstrap view plus concrete parent actions: resume an existing owner,
admit a reconciled replacement, integrate an existing exact-head PR, repair a verified setup gap, or retain
an affected fence. Prepare new pinned packets only after the relevant scope and obligations reconcile.
No crash-recovery report grants dispatch or effects; native adapters recheck their own admission.
