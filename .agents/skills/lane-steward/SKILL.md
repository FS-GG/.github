# Diagnose useful parallel work

Use [work-board](../work-board/SKILL.md) for current membership, ownership, capacity and action admission.
Compare actual Deliveries, native/plan prerequisites, owner/PR/worktree, expected outputs and touch-sets.
Read source before suggesting narrower scope. Never narrow below the files or shared outputs the work
really changes. A missing declaration is an intake gap; Outcomes and investigation scope are not made
assignable by inventing paths. A blocked parent/sibling is not an automatic prerequisite.

Propose the exact narrower declaration or meaningful Delivery split to its accountable owner in the
existing issue/thread, with evidence and remaining conflicts. The owner and selected qualified path
must recheck actual reservations and conflicts before changes or execution. Diagnosis does not select,
claim, enroll, edit another owner's scope or establish safe concurrency. No V1 scan/lanes/set-paths,
widen, take or claim route is authorized for organization V2. Preserve original known/Unknown holds.

If no useful parallel work remains, name the actual dependency, capacity or overlap constraint and its
reopening event. Continue eligible serial work through work-board; do not create reporting-only workers,
new queues or scoring ledgers. Success is useful accepted progress within real capacity, not lane count.
